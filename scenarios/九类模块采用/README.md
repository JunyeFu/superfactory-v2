# 九类声明与跨类别采用

`python 检查分类采用.py`检查九类登记及目录所有声明的共同字段、实际载荷、文件引用和跨类别绑定，再输出[有限采用预期](expected-category-adoption.design.json)。S03-03复核增加逐类首版/七项后置、显式模板种子、纸包装成果交接及外部Agent/连接器边界。当前共15个有限预期，原10个业务预期保持。这是设计文件一致性检查与有限推理，不是注册器、软件导入、纸包装求解或生产运行。

设备示例明确选择独立齐套规则；shell/pcb/fastener角色对应实际端口，资源assembler对应同一个R1。输入2壳体、1PCB、4螺钉的声明配方只能形成1个装配体，原输入保存组成而不重新可领。独立媒体只绑定部分锚点，未绑定端口可在属性表待补，不篡改配方。

准备任务设置指定目标的ready，不生产板件；板件样例不表示实现贴装专业内核。服务源14kW是后置服务契约的声明容量，两个各6kW阶段在无背景时合计12kW；不能读成14件库存、已用14kW或首版已实现服务执行。数控提供者available_modes为空，其intended_modes仅保留后续研究，不生成成功结果。

模板采用到已有工程默认不带样例库存/需求，已有工程的库存/需求保持；新建工程可以显式选择自建演示种子，作为新方案输入并重映射对象引用，不能恢复模板旧运行。两个入口分别检查，不以“导入不复制库存”删除合法的显式初始输入。

首版真实专业只纸包装：实际计算→artifact→人工acceptance→consumer_binding→工厂运行。所需计算检查Pass仍须匹配产品版本、用途、单位/坐标、必需内容和人工认可；Fail/Undetermined可保存检查成果，不能绑定为合格包装条件。声明过程不能完成真实纸包装计算；计算、认可和绑定均不产生库存。

本平台MCP桥P3-04是首版任务；Unity/Blender/FreeCAD连接器P4-03后置且实际能力为空。外部Agent经同一宿主Commands调用，不能自建库存/时钟或伪造人的认可。精确字段、错误码与算法仍由S06详细设计落实。

原目录/公共清单例均是design。实际实例化、别名映射、工具与GUI效果由P0/P3实现后验证。主规则见[九类协议](../../docs/03_架构与契约/九类模块清单与消费者.md)。
