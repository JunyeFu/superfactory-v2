# 从空工程搭建一座控制盒厂房

这是完整的设计任务与可复算预期，不是已运行产品。AI图为界面预览；图中的布局、条带宽度和资产树不是计算数据或现存三维模型。以本目录JSON和下表为准确输入。厂房自建样例不对应真实企业、工艺或实际质量结果。

## 目标和八步任务

从空白24m×16m厂房开始，交付6套自建电子控制盒，观察0—600秒。图包在[知识库](../../../模块研究/从零搭建案例图包/生成记录.json)。

|步骤|人决定什么|软件需处理什么|接下来用到的成果|
|---|---|---|---|
|1 新建|厂房尺寸、产品数量、相对起点与班次|空工程和两张画布|共同对象和时钟|
|2 定义物品|每套1壳体、1采购PCB、4紧固件、1空盒；分批来料|BOM、存量、未来到料|齐套和唯一归属|
|3 配置设备|静态图、阶段、数据标签与已支持操作|外观与行为分别保存|可插入产线的设备包|
|4 搭建产线|布局、串并联、缓存、人员与小车|固定设备和移动资源分开|完整生产拓扑|
|5 对齐接口|认可加工作业、端口、单位与支持范围|物品/信号/工程成果分别连接|可供下游消费的作业|
|6 安排时间|工时、资源阶段、检验预设与优先规则|共同时间轴，等待不算有效加工|可说明的生产过程|
|7 改变到料|仅将第二批PCB从240秒改到420秒|齐套等待→缓存满→小车等待|同起点方案对照|
|8 交付|接受的方案、假设和素材|可编辑设计包，结果仍留空|别人可继续修改的工程|

工序：毛坯→CNC→小车→壳体缓存→齐套装配→检查；PASS→包装，FAIL→返工→复检。PCB、紧固件直接进入装配；空盒只进入包装。不能把包装外观直接接到装配BOM。

## 输入与资源

6毛坯、24紧固件、6空盒在0秒；PCB前3片在0秒，后3片在240秒。只有一台CNC、装配台、检查台、返工台、包装台，一辆载量1的小车，壳体缓存容量2。库位是逻辑位置，不额外增加机器。三人：W-C负责CNC上下料，W-A共用装配/返工，W-B共用检查/包装。初始壳体、装配体和成品均为0。

|工作|声明工时|占用规则|
|---|---|---|
|CNC|上料10＋自动45＋下料5秒|机器全程60秒；W-C只占前10和后5秒|
|小车|去程10＋返程5秒|待接收时仍持有物品与资源，接收后才返程|
|装配|40秒|W-A与装配台共同占用，开工按完整BOM领料|
|检查|10秒|W-B；第3件首次FAIL，其余PASS，复检PASS，均为预设|
|返工|20秒|W-A；就绪返工优先于新装配；保持装配体身份|
|包装|20秒|W-B；仅放行件进入，消耗1空盒，装配体保留在箱内|

除小车运输外，工位间移交瞬时；各工位输出接收位按本例最大6件设容量，不另加隐含运输。支持真实走动、工艺准备或更多检查时必须显式增加规则与时间。

第3件：首次检查230—240→返工240—260→复检260—270→包装270—290。基线第4壳体250秒到达，等W-A到260秒。延迟方案380秒只有3成品，shell004/005在缓存、shell006仍在小车，PCB可用0；紧固件剩12、空盒剩3、毛坯剩0。420秒PCB到料，装配4领走壳体释放位置，小车同一时点接收shell006，425秒返程结束。

手算值不证明软件性能或工业收益。复算：`python 推导时间轴.py`；输出[预期时间轴](expected-timeline.design.json)，实际产品验收仍由P1/P2执行。

## 模块足够吗

九类已有模块资产足以分类本例，不需要第十类。已有固定转换、齐套、分流、返工、包装、批次运输声明样例可以复用；**阶段资源、到料日历、类型化专业成果接入、全厂时间轴仍待实现**。CNC采用声明工时，未调用NC求解；检查读取预设，不包含ONNX准确率。更换为专业计算后，应把认可结果接入同一端口，而非再造一套库存。

详细设计直接落实在[接口规格](../../docs/03_架构与契约/专业作业与模块接口.md)、[全厂时间轴](../../docs/03_架构与契约/全厂时间轴与阶段资源设计.md)和任务清单P0-01/P1-03/P2-04。设备图片的Hold/Confirm为拟议能力，首版未支持时禁用；数据标签读类型化值后格式化显示，不能从截图里的String标签反推领域类型。
