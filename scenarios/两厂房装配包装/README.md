# 两厂房：采购件装配、运输交接与单件装盒

状态：完整工程声明设计，未在引擎中执行。该样例为后续开发和路演组织过程，不是企业案例或实际产能记录。

## 文件与工程

- project.design.json：两厂房、两条线、两台工位、六个逻辑库位、三名分别分配的人员、五类物品、供货关系和一张订单。
- variants.design.json：A原方案与B补齐PCB方案。B只新增pcb-002，不改变人员、工时、布局、运输或容量。
- expected-events.design.json：关键事件的手工推导、观察窗结束时的数量和推导算式；actual_result保持空。

H-A从采购壳体和PCB形成装配体；搬运人员在H-A装载、送至H-B并卸载，再返回H-A。H-B将一件装配体装进一个空纸盒，形成成品包装。来源/目的库位为库存和交接位置，不把它们假装成已设计的仓库设备。

工序模块见[装配台](../../modules/devices/manual-assembly/README.md)、[装盒工位](../../modules/devices/carton-pack/README.md)、[批次搬运](../../modules/transport/batch-transport/README.md)。所有尺寸、容量、工时与运输条件均为演示假设。

## 基准参数

|参数|值|作用|
|---|---|---|
|装配|60秒/件，装配人员1名|壳体1件＋PCB1片形成装配体1件|
|搬运|装载10秒、去程30秒、卸载10秒、返程30秒|每批1件；货物接收后可包装，人员返程后才接下一批|
|装盒|15秒/件，包装人员1名|装配体1件＋空盒1个形成成品包装1件|
|来料|壳体2件、PCB1片、空盒2个|B方案仅把PCB补至2片|
|目标与窗口|订单2个成品包装，截止240秒；观察0—240秒|不是行业节拍、全年产量或市场规模|
|跨厂供应|日目标2件装配体，发运窗口0—240秒|当前已接收量附时点，不能把四分钟视为完整工作日|

三名人员分别做装配、搬运和包装，资源不能混用。模板不预设以后来料、故障、报废或额外人员。

## 可以看见的过程

|关键时点|A缺PCB方案|B仅补齐PCB方案|
|---|---|---|
|0秒|开始首件装配|同样开始首件装配|
|60秒|首件完成、搬运人员装载；装配台等待PCB|首件装载，同时开始第二件装配|
|70秒|首件发出，进入在途|相同|
|100秒|抵达H-B并卸载|相同|
|110秒|首件接收入库并开始包装；搬运人员返程|相同|
|120秒|没有第二件|第二件完成，等待返程中的搬运人员|
|125秒|首个成品包装完成|相同|
|140秒|搬运人员已返回，无下一件可发|装载第二件，等待结束|
|150/180/190秒|没有下一批|第二件发出/抵达/接收，随即包装|
|205秒|成品仍为1个|第二个成品包装完成|
|220秒|运输资源空闲|第二次返程完成|

以上为关键时点预期，不是穷举运行事件。首件成品时间=60＋10＋30＋10＋15=125秒。第二件120秒完成，但搬运人员140秒才可用，故其成品时间=140＋10＋30＋10＋15=205秒。新增PCB后第二件等待运输资源20秒，不能仍把全部等待都标成“缺料”。

数量的材料上界是min(壳体、PCB、空盒)，A最多1个，B最多2个；达到上界还要满足人员、时间、容量和运输条件。这里手算表明本例在240秒内可达到对应数量，实际引擎仍须逐条验证。
