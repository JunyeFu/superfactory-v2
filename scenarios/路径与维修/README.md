# 路径物流与维修恢复的贯通预期

全部输入自行构造，工时/速度/处置不是行业数据。`python 推导路径维修预期.py`输出[15个有限预期](expected-logistics-maintenance.design.json)；[输入](inputs.design.json)和主规格对应。此脚本不实现通用运输或维护引擎，没有实际软件/车辆/设备验证。

## 九个运输变体

|变体|条件|预期接受/可再用|
|---|---|---|
|移动后的固定时间|去返程仍声明10秒，装卸2/3秒|15/25秒；不把布局变化当时间已更新|
|认可10m路径|1m/s，装卸同上|15/25秒|
|移动后认可20m路径|路径接入明确|25/45秒|
|先空驶5m|车辆不在取货点|20/30秒，不瞬移|
|双向8m共享区|A/B2秒同时就绪，区外装卸位|A/B接受13/21，返回26/34秒|
|A接收20秒才有位，区外候车|道路释放、车辆仍持货|A/B接受23/21，返回37/29秒|
|同样接收条件，两端均无区外位|A待接收/卸载、B卸载均占共享区|A/B接受23/34，返回42/50秒|
|认可路径失去一条边|不直接连到目的|待重接，接受时刻为空，货物仍在来源|
|两位置相互等待|A持P1等P2、B持P2等P1，无后续释放|显示占用链，不瞬移或复制位置|

共享区的去返程都使用同一容量1资源；就绪时间优先，其次车辆ID。空车不免费穿过载货车。区外位与库位物料容量分别表达，货物发出后到接受前仍由车辆持有；发出前留来源预留，不提前归车辆。

## 六个维护变体

|变体|明确规则|有限预期|
|---|---|---|
|完成当前再停|30秒停新作业，60秒做完、80秒接收；维修20、复核10|维修80—100，第二作业110—170|
|保留在制恢复|0—30有效；维修人40可用、备件50到；维修20、复核10|原物品80—110续剩余30秒，有效总60秒|
|终止移交隔离|30—35移交；第一件不续做，第二件是原计划需求|维修50—70、复核70—80，第二件80—140；隔离件保留，不自动补产|
|复核FAIL|维修完成但不放行|完成时刻为空，原作业/进度保留|
|中断策略缺失|不自动选恢复|待处置，维修/生产不伪造完成|
|已知硬停窗口30—80|60秒阶段必须连续完成|0—30不够，不开工；80—140执行，不从日历推导备件消耗|

维修人实际修理20秒；等待备件不是20秒维修人工。设备当前排他使用由原生产/处置、维修、复核、恢复生产顺序交接，resume_ref不复制容量。在制持有者与设备使用者可以不同，但不会复制货物。所有actual_result为空。
