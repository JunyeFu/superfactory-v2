# 并行准备、齐套总装与有限返工

设计样例，未执行软件仿真。project.design.json提供一厂房、四个线组、六台工位、四名分别分配的人员与十个库位；cases.design.json提供三个明确的检验输入对照。所有工时和结果为演示假设。

壳体与PCB支线各从2件原料开始。壳体加工30秒/件，PCB准备20秒/件，分别生成shell和pcb；总装60秒/件并按1:1齐套。随后检验10秒，必要时返工20秒再复检，合格后装盒15秒。各人员独立分配，不被多个工位共用；各加工设备单件处理。

## 手算过程

|时点|事件|画面应解释什么|
|---|---|---|
|20秒|首片PCB准备好|总装仍等壳体，不能只来一个输入就开工|
|30秒|首件壳体加工好，总装首件开始|两支线按BOM汇合|
|40/60秒|第二片PCB/第二件壳体就绪|第二套齐料等待总装人员与工位|
|90秒|首件总装完成并检验，第二件总装开始|不同资源支持并行，总装与检验可同时运行|
|100秒|A/Q首检失败进入返工；U结果缺失保持待判|预设结果驱动去向，画面不自动判断合格|
|120秒|A/Q返工完成并重新检验|原装配体ID保持，已完成返工次数变为1|
|130秒|A复检合格；Q复检失败进入隔离|返工次数上限为1；失败不再回流|
|145秒|A首个成品包装完成|同一装配体只计一次成品|
|150秒|第二件总装完成|A/Q可检验；U因首件待判而等待检验工位|
|160/175秒|A/Q第二件检验合格/包装完成|Q仍可完成另一正常产品，不因一件隔离删除整条线|

首件首次总装开始=max(30,20)=30秒，结束90秒。第二件开始=max(60,40,90)=90秒，结束150秒。A首件成品=90＋10＋20＋10＋15=145秒，第二件=150＋10＋15=175秒。

|180秒时的预期|A返工后合格|Q复检失败|U首检缺结果|
|---|---|---|---|
|可交付成品包装|2|1|0|
|隔离物品|0|1|0|
|工位待判物品|0|0|1|
|排队等待检验|0|0|1|
|已经完成返工次数|1|1|0|

Q的隔离物品仍存在，不能领用也不自动报废。U没有任何检验放行决定，不能依据已用完10秒工时就生成合格品。三个对照只改变预设检验输入，说明流程机制，不证明质量算法或工业效率改进。

## 可追踪性与界面

从raw_shell-001跟到shell-001，再到总装输出、返工和包装。产出名称用于阅读示例；实际引擎分配唯一ID，检验预设以原始壳体祖先ID匹配，避免依赖特定自动命名格式。返工不拆解、不换零件；涉及替换件的返修以后需另声明消耗与组成关系变更。

详细档显示支线队列、齐套条件和带文字的返工回流线；简化档保留分支方向和队列数；区域档分别展示合格、返工、待判与隔离。检验详情显示结果来源“预设”、当前物品、结果与已完成返工次数。空闲没有当前物品时不沿用上件结果冒充本件读数。

设备规则见[固定工时转换](../../modules/devices/fixed-transform/README.md)、[检验分流](../../modules/devices/inspect-route/README.md)、[返工工位](../../modules/devices/identity-rework/README.md)。总装和包装复用已有模块。完整约定见[并行与返工设计](../../docs/01_业务需求/并行汇合与检验返工.md)。
