[任务框架/工量/成果里程碑](../04_开发与验收/任务框架与工量里程碑.md)取代每日日程需求；10月30日前备齐材料仍为硬目标。S06全部设计通过后生成最终选题PDF，S07实际准备后进入S08；真实软件/介绍PDF/录像、工业评估和可编辑工程分别验收，不将设计图当完成。八项现行衔接见[联合复核](../04_开发与验收/S01-01至S02-03_联合复核.md)。

## 1. 产品要交付什么

超级工厂是**自由度高、可由社区持续扩展、适配Agent操作的工业模拟平台桌面软件**。用户像使用UML绘图工具一样在画布自由设计产线和厂房，通过时间轴排期，推演物品、设备和资源的全过程，比较产能与交付，再导出评估文档或交出可继续编辑的工程。已选的真实3D、两张常态画布和三档呈现继续保留。

平台开放九类业务概念的定义、编辑、组合、采用与贡献：**物品、固定设备、资源、任务、工艺、物流、厂房与组合、专业计算、表现素材**。人工界面与Agent使用同一对象和操作层；社区可贡献不同设备、工艺、模板、计算提供者和素材，让已有工程持续细化，而非只能选择平台作者预设的机器。

长期目标是让用户通过自建与社区扩展，表达和评估所需的各类工厂。“任何工厂”指平台开放范围可继续补充，不是首版已内置全部行业工艺与物理计算：有适配规则和必要输入时可执行模拟；缺能力时工程可保存并定位待补模块，不把缺模型当已评估。首版仍以三类离散模板、平台闭环及一个纸包装专业闭环验证整条开放链。

首版主用户是准备改线、产品或供货变化方案的工艺/工业工程人员与集成商；非专业使用者通过模板及来源明确的输入参与方案讨论。纸包装是首版接入的一条真实专业主线，用户不必先完成包装设计才能开始搭建普通产线。图片中的讨论提醒生产线模拟已有成熟供应；本次主线是用户确认的产品目标，不把讨论意见当作原创性、商业价值或比赛认可的证明。

完整任务是：**确定目标 → 自建/采用九类模块 → 画布设计产线与厂房 → 时间轴排期 → 执行模拟并逐件追踪 → 修改比较 → 导出评估文档及可编辑工程 → 将可复用模块贡献社区**。必要专业计算和人的认可在对应任务处进入，不要求每个工程经过全部专业工作台。单独生成漂亮厂房、设备动画或指标图不构成任务完成。

用户解决的是“这份方案在声明条件下怎样生产、哪里受阻、能交出什么、别人如何接着修改”。可信工艺输入仍有提供者，不从照片、模型外观或Agent措辞推断真实生产能力。

## 2. 使用者、输入责任与决定

|使用者|何时使用|需要拿到的输入|自己决定什么|完成后拿走什么|
|---|---|---|---|---|
|产业规划中的非专业使用者|讨论新线、改造或厂房分工的初步方案|内置模板、来源明确的社区模板或专业人员提供的工艺，物品需求、场地及供应假设|选择模板、布置组合、改变已公开参数、标明待补条件|看得懂过程、能说明假设的初案和比较结果|
|快速出方案的工艺/工业工程人员、集成商|准备方案、响应产品或供货变化、交接客户工程|BOM/路线、设备能力、工时、资源、来料、质量及接受要求|定义规则和资源阶段、确认工艺与专业成果用途、选择比较条件|可彩排的细化方案、问题定位及可编辑交付包|
|生产/物流/质量等协作人员|核对方案中与自己有关的条件|订单、班次、发运接收、判据与处置规则|确认各自提供的条件、预设决定及适用范围|明确其条件如何影响生产和交付|
|接手者与模块贡献者|继续修改工程，或补齐某类工厂所需模块|交付工程、模块版本、参数来源、支持范围及允许携带的素材|选择九类贡献入口，定义/试用/采用模块，修改并重跑、准备贡献|可被继续采用的工程、模块及适用说明|

这几类是业务责任，可以由同一人承担。首版不因此建立企业账号、部门审批或在线协作系统。教学使用属于可能的相邻用途，不代替首版面向方案作者的验收。

“非专业”指不要求用户编写仿真代码或制作完整CAD，并不指完全没有输入也能得到可靠工厂结论。只有外观或布局资料时允许保存草稿；影响当前彩排的工时、物品/资源和连接缺失时指出缺项。缺成本不阻止已有条件下的时间彩排，但不据此输出完整成本。

内置及社区示例用于开始搭建和理解规则，不要求用户先聘请专业人员才能编辑；用于真实项目判断时，方案作者仍须确认示例参数是否适用于自己的条件。系统保留参数来源和待补状态，Agent可协助整理已有输入，不能把默认示例变成实测事实。

|UT-04 完成纸包装工程|提供产品版本、结构/材料/连接与成型、开合、取物要求；人决定认可用途|执行首版支持的专业检查，形成制造层和可编辑成果；将认可成果绑定到包装工位|实际专业结果与下游装入条件相连；未判定不显示通过，旧成果不会自动用于不匹配的新产品|SF-12、13|
|UT-05 彩排并解释问题|选择方案、观察窗与接受目标|推进共同生产时钟，显示作业、到料、占用、在途、接收和物品经历|能从等待或未交需求定位物品、资源与条件；显示当前可证明的阻断，不自动宣布唯一根因|SF-06、07、08、11|

用户工作链与生产物料链是两件事。生产参考链为“来料/加工或准备 → 齐套装配 → 检验/返工 → 包装 → 接受”，采购完成的零件可以进入相应工序，不必经过本软件中的全部专业工作台。

任务可以按需要反复执行：UT-02/03用于修改设备与生产条件，UT-04只在方案需要纸包装工程时进入，UT-05/06形成彩排—修改—比较循环。UT-07可保存草稿或交付完整方案，但草稿缺项、尚未运行与已有结果必须明确区分。完整首版演示需包含专业主线，不意味着每份用户工程都必须使用纸包装模块。

### 画布设计、排期与产能的成功含义

用户在流水线画布新增、移动、复制或编组设备，并用有输入输出含义的连接组织串并联流程；连线须能说明物品去向，单纯视觉相连不自动构成有效工艺。设备详情配置能力、耗时、用料与资源，整线移动保留内部连接。

用户还可向已连接的外部Agent用一句话给出行业/产品、日产目标和场地长宽高。Agent借助行业×场地生成模板、九类概念库与skills实际操作平台，生成详细可编辑布局/物料连接/资源/排期，检查场地条件并运行，用真实接受量与等待解释是否达标；初案达标直接交付，不足时按反馈有限修正或列出缺项，再导出报告。详见[目标驱动厂房生成](../03_架构与契约/目标驱动厂房生成.md)。这是首版Agent能力要求，不能只提供接口草案或图片；当前实现仍待完成。

底部全厂时间轴同时提供计划输入和计算结果。用户可编辑订单释放/期限/优先序、到料时点、人员班次、换单与工序阶段耗时；系统根据齐套、依赖、资源与接收容量计算实际开工和完成。计划拖动不承诺那个时刻一定开工，拖动结果显示位置不能改产量；现阶段不增加自动最优排程。

在明确的观察窗和目的接受口径下，结果须说明已接受多少、还有多少未完成、已完整交付订单的完成时刻，以及物品/资源/容量造成的等待。窗口产出是该方案条件下的彩排结果，不是脱离订单与输入约束的设备额定产能；未输入需求或供给时不能自动宣称满负荷极限。

## 4. 首版覆盖范围

|范围|首版承诺的目标行为|边界与交付责任|
|---|---|---|
|工厂类型|机加工交付、外购件总装、机电支线并行制造与总装三个可编辑通用离散模板、纸箱制造目标生成配置及空工程|复用同一核心；非纸包装专业工序采用明确的声明过程，不表示NC、电子装联或工业物理已求解|
|共同生产业务|产品/订单/BOM/路线、阶段人员、到料、班次换单、齐套、检验返工、包装、固定时间批次运输、厂际供货、逐件追踪、时间轴和比较|行为与参数需有来源；不能靠外观、图标数或每日目标直接生成库存|
|真实专业主线|有限厚度板片、折带、固定连接和多件纸包装；受限折叠容器、外盒/内衬、罩/滑套三类机制|保留产品/功能、材料、构件关系/重复订单三类变化；实际检查成型、开合及固定姿态直线取物，输出刀/折/胶SVG、材料/数量表和可编辑成果。不是单盒动画或尺寸比较器|
|专业结果使用|区分Pass/Fail/Undetermined，成果、人的认可和工厂消费者绑定分别保存|认可的包装规格影响包装工位接受；专业计算不直接增加成品。未证明的强度、防护、食品接触、现场节拍不能随几何结果一并承诺|
|九类自定义|类别自己的定义/参数/组合/采用入口；设备支持插图与声明数据流、序列/GIF/模型/原生部件和标签|用户用表单与规则创作；更深计算由真实提供者扩展。定义可保存不等于能力已可执行|
|Agent|按产品/日产目标和场地匹配模板及九类库，填参布置/连接/排期，静态检查、渲染、运行后达标直接交付、不足时有据修正/比较、逐件解释并导出报告|与人工共用操作；只调用实际公布能力，认可与社区发布保留人的决定，不另建生产状态|
|运行和交付|Windows本地桌面，普通编辑/模拟/保存离线；PDF/HTML/CSV/JSON评估输出＋可编辑目录/工程包|技术栈沿用已选方案；评估报告、工程包与赛事代码/介绍/视频分别交付，见[报告规格](../03_架构与契约/评估报告与数据导出.md)|
|社区扩展|九类均有贡献起点、示例、版本/许可、复现与采用说明；作者可补行业能力并分享|首版用本地包和仓库Issue/PR，不要求在线商店；社区内容不会自动升级工程|

“声明过程”仍要由共同彩排引擎实际执行输入消耗、资源占用、耗时和输出规则，并产生可追踪结果；它不是静态摆放或预录动画。它不求解数控刀路或电子装联物理。纸包装则在同一平台中增加真实结构计算、检查和制造层成果，两种能力的输出责任不能混同。

首版负载目标为3厂房、60设备、3000件物品，是未来验收条件，不是当前性能、行业覆盖比例或工程大小禁令。首版21项任务（含P0-03部分范围）、7项后置，以[任务选择](首版任务选择.json)为准；材料准备时间沿用[交付基线](首版交付基线.md)。

41个专业方向继续作为研究储备。复杂路径/交通、停机维修、建设投用、公用服务、其余40个专业内核、软件在环和Unity/Blender/FreeCAD实际连接器属于后续；其设计资料保留，不能出现在首版“已支持”清单中。无界全局最优搜索（SF-17模板填充必做；初案达标直接交付，有限反馈修正能力以不足案例验收）、云端市场及多人协同也不进入本次首版。

## 5. 对象和观察边界

- **物品**是流动、存储、消耗、生成或交换的实物，分类型与单件/批次。包装和回收载具可以流动；信号、订单和专业成果不是实物库存。
- **设备**在彩排运行中固定布置，在方案编辑中允许移动。整线可作为编组移动并保留内部连接。人员、手推车、AGV等按移动资源表达；机械臂部件动作不改变固定设备身份。
- **厂房**容纳设备、库位、资源和线组，通过边界接收输出物品。**基地**是厂房的组织分组；供应商/客户可以是外部边界节点，无需虚构内部设备。
- 常态只有**流水线画布和多厂房画布**，菜单切换。设备操作通过单击进入详情；单厂房总览是流水线画布缩小后的顶点，详细/简化/区域是三档呈现，缩放不进入设备页或另一张画布。
- 设备外观时间轴、工序阶段与全厂时间轴共享明确来源：表现读取实际进度，仿真拥有生产状态。回看、循环观看和聚合不重新生产。
- 仿真结论只适用于所用输入、规则、版本、观察窗和接受口径。实际工厂的预测精度、自动选址/投资决策、连续流/热电求解及真机控制不由首版画面提供。

## 6. 哪些内容可以据此开发，哪些仍需下一检查项

从本文件可确定主用户、需要提供的输入、人的业务决定、七项完整任务、首版/后置范围、交付物及观察方式；需求、界面和任务实现不得另造不相容的产品目标。

具体Rust字段、保存schema、操作签名、LOD切换阈值、纸包装算法及依赖版本尚需各自后续检查项落实。本文件通过只说明产品定义已清晰，不宣称这些详细设计、编码、运行或用户验收也已通过。

截至本轮，S01-01的产品定义交付和该层文档证据均为100%（既有1/1记录）；运行效果不在这个百分比内。S01-01/S01-02的联合缺口与实际处置见[完成口径及补缺](../04_开发与验收/检查项逐项复审.md#两项完成口径与补缺处置)。
