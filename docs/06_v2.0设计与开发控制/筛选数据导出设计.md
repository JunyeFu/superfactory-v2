## 1. 从数据页到实际文件

数据页取得有效查询后，用户点击“导出此筛选全部结果（CSV＋JSON Lines）”，选择真实目录，跟随原异步任务。导出捕获该次筛选和已显示的选择，从第一行读到末页；当前页位置、UI分页大小不作为导出行范围。修改筛选不改变已启动任务，也不控制生产。

|视图|具体落点|
|---|---|
|任务交互|一个导出按钮、原目录选择及任务进度；没有有效结果时先查询|
|结构数据|H11 export_cloud_data、固定选择、JSONL记录、CSV和紧凑文件回执|
|状态行为|固定dataset/F/设备集合或执行revision；逐页写入后提交新目录|
|接口协作|复用C08/TX07、C12来源目录及原Task权限；无新增云HTTP端点／表|
|界面消费|当前页读取完成与全部结果文件完成分开，失败／取消保留实际任务状态|
|部署验证|DE01—08和百万全量流式导出；没有实际运行结果|

H11新增Project作用域Host操作export_cloud_data，返回现有exporting种类的Task，输出新cloud_data_export分支。参数含当前Project修订、原typed DaaSQuery、固定选择和本调用者真实SelectedFileRef（purpose=export_cloud_data）。不接收任意路径、URL、token或待写数据。

H09原请求查询增加H11的第四registered分支，同请求同参数仍返回原Task，不同参数冲突。H10/H11都返回exporting handle，因此把设计名统一为ExportingTaskHandle，只在HostOkData中保留一份该形状；实际get_task仍按不同originating_operation及输出分支核对，避免重复oneOf导致歧义。

## 2. 固定完整选择并从头读取

telemetry选择携带实际首响应的cloud_project、dataset、selected_visible_frontier和selected_device_ids。目录前沿不能代替查询前沿。H11用原语义筛选、固定选择和page.limit=200从头读；UI先前的page.cursor不带入导出。

C08每页新增selected_device_ids：空输入[]在固定F内解析出授权且已出现的遥测设备集合；显式已授权设备即使无记录也保留。集合按ID排序，游标保存规范设备集合。后续授权或范围变化不能悄悄换成另一组设备；每页仍须通过实际授权。pin不是grant，也不证明调用者曾看过某页。

原始遥测起始游标after_ingress_id=0；分钟聚合起始after_row_index=null，表示第0行之前，后续游标仍用实际末行索引。不能用数值0表示分组起点而漏掉首行。H11重放已选设备列表；若固定列表为空，响应仍须解析为同一空集合，否则失败而不是导出另一范围。

执行查询则把已显示选择解析为精确revision并与identity固定，从cursor=null开始，不在下一页重新取latest或cutoff。行类型须对应原aggregation，页内行数≤200、顺序连续、选择一致；直到next_cursor=null才结束。

telemetry来源模式从实际授权C12 DatasetDescriptor取得，存入文件头／回执，不从observation用途猜测。其目录frontier只是目录元数据，导出覆盖仍取固定F。执行投影的descriptor为null，不能据此猜成物理或软件设备来源。

## 3. 两个可逐页写入的文件

导出目录为选定目录中的新cloud-data-<export_id>子目录，内容固定data.csv和data.jsonl。JSON Lines不是单个JSON文档：每行一个合法JSON值，按顺序保存一次header、至少一个page、一次完整footer，标准库可逐行读取。

|记录|内容|
|---|---|
|header|export/Project身份、原规范查询及固定选择、实际目录来源、生成UTC元数据、CSV列及值编码|
|page|从1开始的连续page_index和完整原DaaSQueryResult，包括本页数据、选择、next_cursor及质量问题|
|footer|真实页数、行数、逐页质量问题出现次数及complete=true|

空结果仍生成CSV列头和JSONL的header／一个空page／footer，行数为0，来源／筛选不丢失。生成UTC只作文件元数据，不代表请求到达或文件提交时间。质量问题出现次数不声称是去重后的问题数。

CSV按原始遥测、分钟计数、执行明细、接受量、命令计数、等待时长选择固定列，具体字段在结构化设计。原始复杂行保留完整payload_json，数量保留精确coefficient／decimal_places／unit，时间保留原UTC微秒字符串；source_row_index、export_row_index、ingress_id各自命名。

CSV数据格采用json_value：先把typed值编码成JSON文本，再按普通CSV规则转义；独立消费者先csv读取，再逐格json.loads。字符串保留JSON引号，null就是null，嵌套值保留对象。此规则明确保留字符串、换行、精确数量及缺项，不经浮点近似或空格补零。

工作器只持当前页、写缓冲和计数，边读C08边写两文件；不汇集百万行Vec，不调用报告PDF生产者或打包整个ProjectArchive。独立授权客户端也可自行流式消费C08，H11负责本机／Agent的真实选目录交付。

## 4. 目录提交、取消及错误

现有[write_evaluation_directory](../../packages/commands/src/project_store.rs:1529)使用隐藏stage、新目标及MoveFileW，且拒绝覆盖已有目录；其输入是内存文件和工程归档，不能直接视作百万数据流式能力。

L22需增加数据专用的固定两文件stage句柄和提交接点，复用实际Directory及Windows不可覆盖重命名语义。L68工作器在Host锁外读网络／写文件；所有页、footer及flush／close结束后，按原Task／目录授权规则核对，并在发布前检查取消。目录rename是提交点。

提交前取消或网络／权限／行型／磁盘／rename错误，任务不得返回完成目录和成功FileRef；隐藏候选按既有策略保留，不修改旧有效目录。提交已成功时，竞态取消不能撤销文件或删除结果。取消只作用于导出，不停止生产、设备或云写入。

Task结果仅返回实际export_id、查询／固定选择／目录来源、计数和两个真实FileRef；不把全部导出数据放回get_task。UI／Agent核对原request、scope、exporting种类、cloud_data_export输出及实际选择，不能把H10报告回执错认为数据导出。
