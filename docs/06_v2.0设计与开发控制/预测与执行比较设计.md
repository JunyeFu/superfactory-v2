# v2.0预测Run与云执行比较设计

2026-10-26。**仅设计；v1验收优先，v2实施门关闭。** 本文件补T8-A07/F06/F16的设计缺口，不以两次执行的比较替代“本地预测Run与云执行”。[结构化设计](预测与执行比较设计.json)及[接口草案](接口契约.schema.design.json)更新为sf.execution/2.0-draft11；实际来源、运行和四格式输出尚未验证。

## 1. 用户工作流与来源

用户在原报告区选择已有终态预测Run、一个明确修订的云执行源及真实导出目录；Host读取两者各自冻结输入，形成同一报告对象，再输出所选格式。选择不会新建Run、取消计算或启动生产。原一／两执行会话报告和执行间比较保持；新增预测比较是独立字段。

|视图|具体设计|
|---|---|
|任务交互|从当前工程实际Run列表选择预测，再指向已选执行源；可明确不选预测|
|结构数据|实际Run引用、预测摘要、执行引用、条件和可空差值；不把Run改成ExecutionSnapshot|
|状态行为|冻结终态Run；未知指标保留null；有效但不可比时并列呈现|
|接口协作|复用get_context/get_run及H10；无新Host／HTTP操作或表|
|界面消费|模型预测与软件在环／真机执行分列，显示各自窗口、单位、前沿和条件|
|部署验证|PE01—08及同一canonical四格式，实际出口全部待执行|

现有[RunInputRef与RunResult](../../packages/domain/src/models.rs:2150)分别记录冻结输入和真实软件计算结果。[evaluation_inputs](../../packages/commands/src/host_evaluation.rs:364)已经按Run读取原冻结工程、场景及精确模型；[指标生产者](../../packages/reporting/src/metrics.rs:68)保留实际接受事件、订单／保存目标及重叠口径的未知语义。新报告沿用这些来源和精确运算方法，不调用Engine补结果。

## 2. 选源、权限和冻结

H10新增必填可空prediction。非空是PredictionExecutionLink：prediction包含真实RunId及预期ReportRunInputRef，execution包含read_origin、精确identity和execution_revision，并且必须属于H10的sources。调用者不提交RunResult、计算指标、冻结文件路径或接受量。

只接收同一实际授权Project的Project-scoped Run，拒绝DefinitionDraft、其他工程、非actual_software及身份冲突。Run须处于completed／failed／cancelled终态；running／queued／paused不作为不可变报告来源。非终态明确报错，由用户另选或等原任务结束，H10不自动控制它。

实际冻结Project／Scenario／模型缺失或与所选引用冲突时导出失败，不按当前草稿代替，不重跑预测或静默省略。合法终态Run若未产生计算前沿，可保留真实状态，但受影响指标未知。它和“冻结输入根本不存在”是两种结果。

Host短锁内授权并取得原Run记录、不可变描述和请求身份；文件／网络读取在锁外，发布前核对实际上下文与权限。执行可来自云端精确R／F，预测仍来自本机真实工程归档，不新增Run云上传。原Host或归档缺失时不能重建预测；用户仍可明确提交prediction=null，导出独立执行报告。

报告使用已有ReportRunInputRef的工程／场景ID及修订，不带私有frozen FileRef或绝对路径。[该类型](../../packages/domain/src/models.rs:3379)只在设计schema中增加复用别名，不修改旧Run持久化。

## 3. 可比条件按实际输入确定

先对照真正冻结的typed内容，不能从相同修订号推断内容相同。首个切片明确忽略Project的revision/title/views，其他实际字段保留；设备几何、物料、资源、路线、BOM、日历、绑定、初态和生成目标都在比较内。Scenario只忽略revision/project_revision/title，window按指标单独判断，其他输入保持完整语义。未证明不影响结果的差异不能自行忽略。

模型比较包含精确引用及实际定义；同ID／版本却内容不同也不可比。云候选映射须对齐冻结模型中的设备、动作、端口和资源；实际选派设备允许不同，这是执行结果的一部分，不误算成模型输入差异。固定历史中的设备可用性变化同时展示，但不能仅凭它认定因果。

接受口径使用实际产品修订、单位、接受位置和阶段；必须唯一对应固定正目标。多产品重叠或共享目标缺分配时保留未知，不能把同单位数量直接相加。其他输入不等价时仍可并列展示两份真实结果，受影响差值为null并列具体原因。

## 4. 两类偏差分别判断

预测摘要记录原计算状态／窗口／前沿、goal_met、模型虚拟时钟、模块版本、实际声明目标、分口径接受量、由实际接受事件确定的目标时间及缺项。accepted不使用旧RunSummary的汇总快捷字段；无前沿、重叠口径和缺目标分别处理。现有build_evaluation对缺计算前沿会拒绝，新摘要须显式表达这一缺项，不能宣称旧函数已支持。

|指标|允许相减的条件|结果含义|
|---|---|---|
|目标时间偏差|同输入／模型／固定目标和接受口径；预测已由指标证明达标，执行已达标且义务结清；两方时钟起点明确|执行Host目标毫秒−预测模型目标毫秒；正值更晚，负值更早|
|接受数量差|上述基础输入口径一致；预测完整计算至原窗口末端，所选执行R／F确实覆盖完全相同端点|该唯一接受口径的执行接受量−预测接受量；用精确SignedQuantityChange|

当前ExecutionPolicy已经把source_prediction_window.start固定为0；预测起点须与其及冻结时间参考对应，执行Host经过时间从首次run开始。这里比较各自起点后的持续时间，不相减UTC时间、设备自报时间或不同虚拟原点。模型时间与Host经过时间的差异始终保留标签。

两个末端窗口不同，会使同窗数量差未知，但不必抹掉已经证明的同目标时间偏差。反之，不能从当前最终库存裁一份过去数量，也不临时重算另一截止Run来凑齐。observational表示至少一个偏差在自身条件下已知；均未知时为side_by_side_only。条件按指标分别消费，不把全部条件机械AND为一个全局通过值。

时间与数量使用既有精确表示；超出共享表示范围则未知并说明，不用浮点近似。这是预测偏差，不是算法加速收益、成本改善或物理有效工时。存在设备变化和观察限制时，报告一并呈现。

预测等待另以PredictionWaitingMetric记录实际模型对象、source_intervals及已计算前沿，复用metrics.rs:196的对象关联和区间裁剪／并集口径；重叠reason不重复加总。没有计算前沿或对象证据时为null，真实已算前缀没有等待才可0。四格式及prediction_waiting表保留这些值。

模型对象等待（虚拟毫秒）与Host逻辑工作各阶段等待分列。只有对象映射、等待定义与覆盖窗口一致才可作同口径比较；缺条件列waiting_basis限制，不给出跨定义等待改善。现有目标时间和数量偏差仍按各自条件判断。

## 5. schema、报告与四格式

预测切片新增7个设计定义：复用ReportRunInputRef，以及PredictionRunReference、PredictionExecutionLink、PredictionRunSummary、PredictionComparisonCondition、PredictionExecutionComparison、PredictionWaitingMetric，当前全体154定义。H10 params.prediction、ExecutionReport.prediction_comparison及ExportExecutionReportResult.prediction均必填可空；省略与null不同。null维持明确的执行独立报告，非空回执须与原选源一致。

|产物|新增消费|
|---|---|
|PDF／HTML|模型预测、执行和预测偏差三个区域；来源、窗口、单位、条件、未知原因一致|
|JSON|同一canonical prediction_comparison，保留null和精确值|
|CSV|新增prediction_sources、prediction_accepted_by_scope、prediction_comparison、prediction_waiting，合计17表|
|Task回执|保留实际预测Run和所指执行源的link，连同原执行stamp及FileRef供UI／Agent核对|

预测CSV只使用report_id／Project／Run及实际目标执行身份，不给Run编造session/epoch。原13表和执行间comparison含义保持；issues表增加预测摘要／条件的具体来源路径。所有格式只渲染同一对象，不各自重新计算差值。未选预测时不渲染预测章节，新CSV表可为空，不填示例数据。

旧Run报告、成本和图片仍可使用原路径；旧Run图片不能标成云执行证据。本切片没有新增模型、分析报表或生图要求。四格式所需真实文件发布、取消、失败和managed大结果仍消费原Host／桥边界。
