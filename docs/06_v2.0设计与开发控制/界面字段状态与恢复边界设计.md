## 2. 字段的实际生产者

字段逐项映射见结构化设计UIF01—14。主要差异如下：

|字段|契约生产者|呈现和操作规则|
|---|---|---|
|准备配置|H08(configuration)的CloudProductionConfiguration|本机受管配置给出允许绑定和缺项；不返回云token。配置读取不是执行准入|
|准备结果|H01准备Task的ExecutionPreparationTaskOutput|成功仅为prepared；另发run才派工，Task完成不代表目标完成|
|设备boot|ExecutionDeviceView.registered_device_boot_id、C13原slot的device_boots|注册身份与观测新鲜度分列；retired/unknown不能显示在线或自动允许接单|
|观测有效期|同R/F/T的latest_observation.observation_probe及pending_observation_probe|待确认／已确认／已过期按Host结论；旧云头显示原观察时点。新probe等待不延长旧期限，Renderer不以本机时间重判或发探测|
|设备资格|ExecutionSnapshot.devices的ExecutionDeviceView|人工允许、设备自报、观测新鲜度分列；未知保留未知，不能由页面倒计时推成空闲|
|派工理由|LogicalWorkView.latest_dispatch_decision、AttemptView.dispatch_decision|展示Host当时已知候选和理由；每次尝试保留实际选择，不由前端重新计算|
|接纳事实|AttemptView、ReceiptAdmission及BusinessFacts|云stored、设备Completed、Host提交、合格接受量分别呈现|
|工时|WorkTiming|名义、Host确认预留／占用、设备自报、物理有效工时分列；缺测量显示未知|
|控制可用性|ExecutionReadEnvelope.access|由实际调用者、原会话所有权、生命周期和权限计算；不是快照中的永久权限|
|同步关系|ExecutionReadEnvelope.delivery|云发布滞后不等同于生产失败；云最后修订不冒充当前实时状态|

ExecutionDeviceView中的有效允许接单只表明设备层条件，不能替代逐工单的端口、物料、资源和日历准入。阻塞理由直接显示Host给出的文本，Renderer不解析文本改变资格。

DispatchExplanation只保存本次需要展示的选择依据，不新建通用审计系统。对当前能够合法准入的候选按预计完成时间、稳定binding_id顺序选择；无合法候选时selected_binding_id为null并给出阻塞原因。忙碌设备的未来预计分配不得作为已发布尝试。该说明取真实准入过程，模型名义工时仍不能触发自动生产完成。

## 3. 补齐桌面的只读入口

初始接口清单缺少数据页读取入口。现行契约采用**H08 read_cloud_production**，通过实际Native授权入口启动cloud_read Task：

1. 当前Project、选择、输入修订和调用权限由Host核对；configuration返回脱敏本机配置。
2. dataset_catalog、active_execution、data_query、snapshot、command、command_receipts、inputs、observations、history分别消费C12／C13／C08／C07／C14／C15／C16／C17／C18。无任意URL、HTTP方法或凭据参数。
3. 网络I/O在ProjectHost锁外的受管worker执行；完成时核对原上下文及权限。Renderer只消费有类型结果，不保存生产云凭据。
4. get_task取得CloudReadTaskState／CloudReadTaskOutput；取消该Task只取消读取，不能停止或回滚生产。
5. 云错误映射到现行Task错误，不能以空表／零接受量冒充失败读取。网络I/O失败可保留本身份上一成功结果并标明其修订、过期和读取失败；明确权限拒绝或Host／Project身份变化时清除受保护视图。这不承诺旧结果仍实时。

H02读取本机实际持有的执行快照（包含只读归档），H09读取同身份本机输入／固定时点观察／历史及受权目录、原请求；控制权另行判断。不持有原会话或原数据不存在时明确缺失。H08可读云最后发布版本。云端自己不能计算Native Host的私有控制权限，云读取的allowed_session_controls及device_acceptance_control_ids为空；H02由实际Host计算当前调用者可用动作。每次H03提交仍重新授权并比较expected_execution_revision。

H08加入实际能力catalog后才向UI／MCP公布。旧Host未实现时显示缺少能力，不偷偷切换到未授权HTTP，也不在浏览器预览中模拟生产状态。

## 4. 表单、查询与异步结果

准备表单保存方案及修订、两个允许候选、目标数量与单位、报告截止。H08配置结果携带基准修订，H01再次验证并冻结。冻结前基准不符则拒绝；冻结后原输入保持不变，即使当前草稿后来变化，也只显示二者差异，不静默覆盖或把当前草稿套进原会话。prepared之后该会话的绑定和输入只读，调整需另一个明确的新会话。

未应用的目标／截止／候选输入参与现有hasUnappliedInput。查询筛选只是当前视图条件，不写工程、不作为未保存生产输入；改变筛选清除旧cursor并开始新查询。查询明确区分UTC云首次存储时间与Host会话毫秒，不能跨钟相减。

一次只保留一个同类观察请求在途。采纳结果须匹配实际Native Host上下文、Project、相应选择身份（执行读含session/epoch，遥测读含cloud_project/dataset）、筛选和最新请求序号；对应身份或筛选变化、关闭面板后到达的旧结果不采纳。取消旧读不是取消生产。

会话控制及设备接单开关在等待H03确认期间显示“提交中”并禁止同动作重复提交；不先改变实际资格。超时或响应丢失时读取原身份和新快照，不自动重发run、改派或未知命令。revision冲突后刷新并让用户依据新状态再次操作。

|状态|可见反馈|允许动作|
|---|---|---|
|无工程／无配置|显示缺少工程或受管部署配置|返回工程／刷新；不显示已连接|
|无观测／过期|未知或过期及Host最后接纳前沿|读取、定位；是否派工由Host决定|
|查询为空|“本筛选无记录”，保留来源与范围|修改筛选|
|无读取权限／缺少能力|明确错误及受影响操作|返回或刷新；不当作空结果|
|publication_pending|本地确认rN、云发布rM分列|继续合法读取；不把云rM包装成rN|
|needs_resolution|列出未知命令及覆盖范围|查询原命令、核对；不提供强制完成|
|历史截止回看|固定cutoff及对应revision|只读，不跟随新快照，不出现生产控制|
|目标已满足但仍有义务|接受量和在途／待输出并列|继续核对；不提前标completed|

### 4.1 数据页的选择、分页与可见完成状态

按[数据查询设计](数据查询与规模验收设计.md)消费draft9。telemetry读的身份是实际Host、Project、cloud_project、dataset、原不可变筛选（含aggregation/page limit）、视图内generation及页请求；它不借当前生产session/epoch作身份。execution查询保持原精确session/epoch/revision。generation只是当前组件的请求关联值，不是新增线上字段或授权。

首查询cursor=null，接受首响应的dataset_id/selected_visible_frontier；目录中的frontier只供发现，不能冒充本次查询前沿。后续页复用原筛选、page limit和原cursor，核对同dataset/F；改变数据集、设备、时间、聚合或分页大小即进入新generation，取消旧观察并忽略晚到结果。先核对真实H08 Task/请求/上下文，再采纳页面数据。

rows查询只接受原始TelemetryRow/GeneratedLoadRow并保留dataset实际来源；分钟查询只接受DeviceMinuteCountRow。当前通用schema联合不能替代请求aggregation与结果行型的对应核对。显示当前页行数；聚合count是该组总数，当前页各组之和不表示dataset总量。data_quality_issues原样呈现，HTTP成功不清除缺项。

|视图状态|显示和动作|
|---|---|
|尚未查询／首查询中|等待本次结果；保留的历史结果须另标旧筛选/F，不混成新结果|
|页就绪且还有后续页|“当前页N行，前沿F，仍有后续页”；允许读取下一页|
|下一页读取中|保留原有效页和选择，禁止重复同页请求|
|末页就绪|标明末页；只有从cursor=null开始的原链所有页成功才可标完整筛选|
|下一页失败／观察取消|保留原页、F和待取cursor，明确未完成；显式只读重试使用原cursor及新request_id，旧Task按原索引核对|
|合法空结果|保留dataset/F和范围；F=0合法，显示本筛选无记录；权限拒绝不能当空结果|

UI可先显示一页供翻阅，H08 Task completed只说明本页已取得。完整逻辑查询计时由专用验证消费者逐页执行，不拿首屏展示时间替代。仅从中途cursor开始的读取，即使到了末页，也不证明前面各页已读完。

云时间明确标UTC，原始微秒字符串在请求和详情中保留；不能用JavaScript Date的毫秒往返覆盖原值。来源合成时间不当作云首次存储或正确呈现帧时间。面板仍沿用一个入口三个页签，不增加查询编辑器、运维面板或生产控制动作。

## 5. 面板离开、切工程与原生关闭

关闭云面板只停止观察、取消只读Task、保留Host生产；返回入口焦点遵从Workbench原行为。再次打开从原identity读取，不重新创建会话。

现有Workbench.activeTask只检查TaskHandle。准备Task结束后Engine仍可运行，因此v2须在Host执行注册表上计算离开阻塞，而非把生产生命周期伪装成一直未结束的准备Task。

|接点|拟议具体改动|
|---|---|
|Workbench.tsx 129／774／780行|加入面板editing、准备输入dirty和实际生产workInProgress；关闭面板与关应用分开|
|windowClose.ts 8／18／32／35／60行|在关闭检查前增加prepareClose回调，停止观察并取消只读Task；回调不执行stop。随后仍读Host并走原finish_close|
|project_host.rs 409／424／439行|DesktopCloseState增加execution_blockers；finish_desktop_close核对当前会话及义务，discard不绕过|
|project_host.rs 3862行|check_departure消费同一执行注册表规则，实际拒绝切工程|
|project_api.rs 87／99／958／966行|消费真实Host关闭状态与最终检查；不能只加前端提示|
|export-engineering-types.rs 3／15行|由实际Rust导出私有关闭DTO及其所需依赖声明，不能手改generated/DesktopCloseState.ts|

拟议私有execution_blockers每项包含session_id、execution_epoch_id、execution_revision和reason；reason至少区分nonterminal_session、unresolved_command、unpublished_final_result。它从现有Host执行状态派生，不另存一份库存或生产状态。

prepared也应明确停止后再离开；stop停止新派工，已有工作继续核对。Host不得在未知工作或最终结果未持久化时正常关闭，避免丢失唯一Engine状态。已结清且最终云快照已确认发布后，网关按TX09／C10完成正常占位释放；读取Task不能因持续轮询让正常关窗永远无法开始。

## 6. 重连与Host丢失的人工处理边界

本轮F15要求工程／会话／命令持久化、重连查原命令和未知结果保留；没有承诺活跃Engine跨进程续跑。人工处理按证据分三种：

|情形|本版处理|禁止的推断|
|---|---|---|
|原Host仍实际持有会话，UI／网络重连|H02核对原identity和接纳前沿；H08查原命令／回执，恢复观察与获准控制|不重新发起生产，不因断连生成新attempt|
|当前Host不持有原epoch，原Host状态未知或已确认丢失且未结清|H08展示最后云快照、原命令／回执、未知事项；只读导出带覆盖限制的原结果，保留slot|不同Host身份、超时或UI刷新都不能证明原Host已停止；不清slot、不标完成、不另派未知工作|
|原Host已发布实际结清的终态快照|获授权网关按既有TX09／C10幂等释放匹配占位，不重新生产|不能把原始Completed当作结清终态；不能修改旧快照补接受量|

“请求核对”只查询并交回原Host的合法接纳链，不是“人工确认完成”。当前不提供人工输入接受量、强制完成、强制释放未知epoch或换身份重新生产的按钮。真正恢复或退役未知epoch需要后续完整契约；本演示不宣称已有该能力。

C14返回命令及最新发布的Host确认；C15返回该精确命令的原始回执页。C15固定数据集提交前沿并逐页校验授权，原始记录的前沿与业务快照修订分别标明，不把它们拼成同一份已提交业务事实。

回看、报告可读取最后已发布快照及原始云记录，但必须分别标明：Host最后确认的业务事实、尚未接纳的设备报告、未覆盖的后续区间。原始回执不能被报告生产者直接计入接受量。
