# v2.0冻结输入与执行观察设计

2026-10-26。**仅设计；先完成v1验收，不实施v2。** [结构化规则与18项案例](冻结输入与执行观察设计.json)和[接口schema](接口契约.schema.design.json)保存本轮具体字段。本文细化V2-01／04／05／07／09，未新增产品源码、数据服务、媒体或运行结果。

## 1. 实际接点与设计选择

现有RunInputRef只包含Project／Scenario身份、修订及两个FileRef；EngineInput另持有冻结Project、Scenario和definitions。HostRun及StoredRunHistory保存内部Run／物品／作业历史；run_additions把真实冻结文档随工程保存。不能把这些事实等同于“云端已经保存执行输入”，也不能让执行会话冒用RunResult。

现有Workbench.source为draft／run；readRunInputs依赖run_snapshot及run_module_version。FactoryPresentationContext、FactoryPresentationSource、FactorySceneProps、时间轴Props和缓存键也明确包含Run身份。新增执行源必须补实际消费者，不能只把标签改为“软件在环”。

本设计选择：

|决定|具体选择|
|---|---|
|V2-A08 冻结输入|捕获实际Engine采用的文档、解析后执行定义、精确模块及素材映射；本机受管归档保存媒体字节，云保存同一冻结文档JSON|
|V2-A09 状态观察|Host记录必要item／job／device／逻辑工作／尝试状态改变，按固定修订／前沿／时点读取；云只存投影，不重算库存|
|V2-A04细化|prepared不启动生产时钟；首次run建立唯一单调锚点，暂停／继续不重置|

EngineInput仍保留原虚拟调用语义。当前engine.rs仅在第2133行读取input.run_id来构造RunResult；外部初始化不能临时造一个RunId。内部采用实际LocalRun／ExternalSession身份区分，共用必要的私有冻结文档、库存和资源状态，由虚拟／外部入口分别暴露对应结果；具体辅助方法布局可由实现决定，不复制第二套库存。

媒体仍随原工程交付，本演示不新增云素材分发产品。云冻结JSON能供授权消费者解释模型和数据；缺少本机精确媒体时，对应三维呈现仍是缺项，不能用近似模型计为Native通过。

## 2. ExecutionFrozenInputs与准备就绪

ExecutionFrozenInputs由Host一次捕获并保持不可变，包含：

- exact identity、RunInputRef、冻结ProjectState及ScenarioInput。
- 精确ModulePackage依赖闭包及既有rights；实际Engine编译消费的execution_definitions与scope。
- 本会话的候选绑定；精确module_ref＋AssetRef到本机archive_file的映射。

execution_definitions是冻结Scenario参数展开后本次执行采用的定义视图，不重新发布为同版本模块，也不改原ModulePackage。显示几何及素材权限仍取精确包；算法、名义工时和已解析参数不能由Renderer另算。冻结文档不得带HostCallContext、grant、云token、SelectedFileRef或任意本机绝对路径。

RunInputRef中的frozen_project_file／frozen_scenario_file须对应实际保存的Versioned文档；不能只有引用而没有文件。资产复制保留原AssetRef身份，通过archive_file绑定指向本会话实际保存字节，不依赖后来当前模块同路径内容。

H01准备Task成功须依次取得：

1. 捕获并验证实际输入、绑定、依赖闭包和已解析参数。
2. 由Native分配的受管执行目录保存冻结文档及所需素材；文件路径不由请求或session_id字符串拼出。
3. C01／TX01确认保存session、冻结输入JSON、dataset和工程占位。
4. Host构造未运行的初始状态、连续观察基线及r0快照；TX06确认发布后才返回prepared。

以上I/O在Host锁外受管执行；业务捕获／回收在短临界区处理。prepared前不发设备命令。冻结前基准修订不符则拒绝；冻结后当前草稿变化，不改原冻结输入，界面显示差异。

准备取消仍可能需要结清已经建立的云占位。未知云提交结果先查询原session／revision；在确实未派工时发布clock_started=false的stopped前缀并按TX09释放。不能只取消UI等待就丢弃云会话。

## 3. 生产计时零点

prepared的coverage.clock_started为false、observed_until_host_ms为0；此时的状态是已确认初始化或控制状态，不是经过0毫秒的实际生产成绩。准备等待不消耗report_cutoff_ms。

首次有效H03 run捕获Host单调Instant锚点，设clock_started=true；后续时间均为此锚点经过的整数毫秒。pause_dispatch只停新派工，真实经过时间继续；resume不换零点，不回补虚拟工时。截止仍按原停止新派工、已准入工作继续核对及不可变截止前缀规则处理。

准备阶段C04可保存原始遥测；H07不能把准备阶段消息伪作已运行的接纳状态。运行后取得有效新观测，再参与设备资格判断与派工。初始状态和同毫秒控制按接纳／记录顺序保持因果；相同0时刻不能覆盖成一次无序状态。

Host重启不能恢复原Instant，也不从归档自动重建Engine。原epoch有未知执行时继续按既有只读核对边界处理。

## 4. 状态记录与发布事务

现有Engine有item_history、job_history和jobs_at，但它们返回旧内部JobState。外部执行采用独立ExecutionObservationRecord，不给缺测量的外部作业强塞旧有效工时字段。

每条记录有连续record_sequence、所属execution_revision、at_host_ms及一种对象状态：

|kind|状态类型|身份来源|
|---|---|---|
|item|RuntimeItem|data.id|
|job|BoundExecutionJobSnapshot|data.job_id|
|device|ExecutionDeviceView|data.binding.device_id；本单工序每设备一个冻结绑定|
|logical_work|LogicalWorkView|data.logical_job_id，保存当时队列／预留及选择说明|
|attempt|AttemptView|data.attempt.command_id，保存当时发布／接纳及回执身份|

只记录对观察有意义的状态变化，包括初始化、真实领料／移交、作业状态及设备接单／过期变化；不按渲染帧或名义加工倒计时造记录。record_sequence从1递增，是Host状态记录顺序；它不是数据库ingress_id，也不是设备sequence。

Snapshot.observation_frontier记为F。TX06必须原子写入新增观察记录、不可变Snapshot、其中receipt_admissions、需要的cutoff引用及head：

- 新记录连续延伸已确认前沿到F；记录修订、时间均不能越过本快照。
- 同记录身份同typed内容幂等，不同内容冲突；云不能更新旧记录迎合新结果。
- 可以合并跳过中间快照修订，但不能丢掉它们引起的状态记录；DB14不对每条记录强加一个可能未保存的中间快照FK。
- 同修订快照比较的是不可变snapshot；附带观察记录按各自身份比较，不把可变增量批次当成整个快照身份。
- 事务失败不移动head、不暴露半个观察前缀；云和Host仍不是分布式原子事务。

## 5. 固定R／F／T的读取

H09 read_execution_view只读本机已持有的inputs／observations／history，并提供受权request查询及动态catalog，无云I/O，不执行Engine。H02本机快照与H09观察必须使用同一identity／revision。这样本地已确认、云尚待发布时也能观察完整的同源状态。

显式选择云来源时，H08的inputs／observations消费C16／C17。输入或观察在本机缺失不能偷偷回退到云旧版本；不同来源在来源条明确呈现。本机加载的旧执行归档可以只读，保存的原Host身份不变，也不因此获得原Engine控制权。

ExecutionObservationQuery固定exact revision R、时点T、ExecutionObservedObjectRef对象选择和分页条件。读取R取得F及已观察上界；T超界明确拒绝。每对象只取record_sequence≤F、记录修订≤R且at_host_ms≤T的最后状态，同毫秒再按record_sequence排序。没有记录的对象保留缺失，不从最终items倒推。

分页使用固定identity／R／F／T／filter，按item、job、device、logical_work、attempt及稳定对象ID排序。cursor包含原选择但page.cursor固定null，并重新核验授权。未知对象类别或其他会话身份明确拒绝，不能安静返回一份不完整的“完整场景”。

执行时间轴可呈现固定R已确认的历史区间；游标T控制三维及所选对象的时点状态。详情不能把R的最终holder、finished或设备标志当成T时事实。开放占用在T处裁剪；缺证据的物理工时仍未知。

## 6. 三维、时间轴与精确素材

Workbench增加独立execution来源。冻结Project及模块供几何／静态属性，ExecutionObservationPage供时点物品、绑定作业及设备状态，Snapshot供同修订业务结果。来源键至少包含实际Native上下文、执行identity、输入引用、R／F／T。

FactoryScene新增明确执行源分支，旧Run props及真实渲染消费者保持原义。物品holder通过当时BoundJob的execution_ref解析设备；可抽取当前槽位布局的纯几何部分，但不能伪造JobState来满足旧函数签名。不会因页面时间过去就转换库存。

时间轴在原dock内使用独立ExecutionTimeline／投影，复用现有时间刻度、行几何和样式；不把ExecutionSnapshot包装成RunResult。回看／拖动／关闭面板只改变观察，不调用H01／H03／H04或发设备命令。

当前协议只有可证实的阶段状态，没有连续动作进度。三维显示已接收的working／completed／waiting状态；没有实际进度就不按名义工时播放完成百分比或推测终端动作。复用已接收模型，不新增材质、动作，也不以此降低原模型质量要求。

拟新增私有Native入口project_read_execution_media_asset，输入为ExecutionMediaAssetRequest，返回ArrayBuffer。它消费真实主窗身份和H09读取授权，校验本机执行归档、精确ModuleRef及AssetRef绑定后读取该次保存的字节；不接收任意URL或路径权限。上下文变化或权限拒绝不能沿用旧媒体响应。旧project_read_media_asset及ObjectSource保持原行为。

## 7. 本机归档与重开

Native受管目录由实际Host配置和安全子目录分配，不从会话ID构造磁盘路径。ExecutionArchiveIndex引用inputs文件、观察历史及各修订快照；记录直接使用本契约版本与document_kind。没有任何记录是Engine检查点或可执行恢复脚本。

工程保存／交接纳入这些SupportingFile及对应素材。新执行JSON沿用DocumentKind.Asset的通用支持文件机制，由v2执行加载器按明确类型严格解析；冻结Project／Scenario仍保存对应类型的Versioned文档。不要把执行输入或状态挂成FrozenRun／RunResult。

保存发布消费现有ProjectStore的原子归档增量方法；索引不得指向未写入的文件。重开时核对身份、文档引用、精确资产及记录前沿，建立只读数据集；不恢复旧grant、活跃Engine或命令发送。该方案尚未经实际归档往返验证，不宣称v1旧读取器已经理解v2执行内容。
