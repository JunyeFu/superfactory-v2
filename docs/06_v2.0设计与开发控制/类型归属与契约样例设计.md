# v2.0类型归属、生成接点与契约样例设计

2026-10-26。**仅设计，v1验收优先，v2实施门关闭。** [结构化设计](类型归属与契约样例设计.json)列出154项归属和26个结构样例；[接口草案](接口契约.schema.design.json)更新至sf.execution/2.0-draft11。本轮没有生成产品类型或执行Host／云服务；文档校验器安装在独立.work目录，产品依赖和锁文件保持。

## 1. 154个定义各由谁持有

|分组|数量|Rust源及职责|
|---|---|---|
|O1：复用值／设计标量占位|9|既有sf-domain值；Id按字段映射实际身份类型，不新建万能Id|
|O2：纯执行／云数据|102|拟domain/cloud_execution.rs；含消息、投影、游标、归档和报告数据，不含Host权限实现|
|O3：Host封套与操作视图|42|commands/api.rs及host_external_execution.rs；任务／读取适配、控制和原请求查询|
|O4：Native私有请求|1|ExecutionMediaAssetRequest，实际主窗边界及工程类型导出|

完整名字列表在结构化文件中，每个定义恰归一组。ExecutionReportSource同时被报告比较引用，保留在纯domain；放入commands会使领域报告倒向Host依赖。现有RunInputRef、Issue等已在domain，schema引用保存在commands/generated目录不表示云服务要依赖commands。

Cloud请求／响应的直接引用闭包和5类解码游标，只能落O1/O2。云crate保持直接依赖纯domain，不链接Host／Engine；公开DTO只是数据类型，不授予Gateway或本机控制权限。Cloud来源的access投影不提供本机控制，界面按钮仍须消费原活跃Host的实际权限。

154是设计定义数，不是未来Rust类型数、生成文件数或覆盖率。私有wire帮助类型、生成根及透明身份包装可以不同，但线上字段、分支、限制和实际消费者必须对应。

## 2. 身份与必填可空字段

沿用ids.rs的string_id规则，拟新增ExecutionSessionId、ExecutionEpochId、DispatchCommandId、CloudProjectId、CloudDatasetId、DeviceBootId、ObservationProbeId七种透明字符串身份。设备／逻辑工作／Host上下文／receipt／work／request继续按既有ObjectId等语义使用；TaskId只标真实异步任务。本地ProjectId与CloudProjectId的映射必须来自实际授权，不能因字符串相同就互认。

当前api.rs第8行的present_nullable及第13行的schema帮助函数已经说明：**允许null与允许缺字段是不同约束**。新DTO中required且可空的字段使用显式必现反序列化与schemars(required)，序列化None为null；TS应为T|null，不是可选属性。domain使用同义窄帮助函数，不为复用它建立domain→commands依赖。

旧TaskState新增originating_request_id保留可省略的兼容语义。选择只把当前model!(TaskState)等价展开成显式struct，给新增字段default／skip_none及TS可选声明，其他旧DTO与旧任务不改。H01/H08/H10/H11来源任务则必须登记原request_id，并由新任务严格视图及生成schema条件约束核对。

字符串常量使用封闭tag／单值枚举；固定null与固定bool须有相应严格wire表示或边界转换。普通String、bool、Option的派生结果不能被当成常量已校验。date-time格式也须由真实格式断言及对应生产／消费验证，String派生不构成证明。

CloudTimestamp另按[数据查询设计](数据查询与规模验收设计.md)收紧微秒/UTC输入输出；其Rust wrapper负责真实格式语义，TS为string，纯domain新增定义数为102。

## 3. 三类TaskHandle视图与原请求恢复

内部仍使用原TaskHandle、统一TaskState和原Task注册表。StartupTaskHandle、CloudReadTaskHandle、ExportingTaskHandle是新操作响应的严格wire视图，先验证全部必填字段，再核对kind并转换原handle。字段缺省必须在Option把它归为None之前拒绝。

|操作／视图|kind／输出约束|接点|
|---|---|---|
|H01准备|execution_preparation；Task结果execution_session，仅表示prepared|实际Task登记／worker、typed decoder、请求查询|
|H08云读取|cloud_read；Task结果cloud_read|受管读取，取消不停止生产|
|H10报告|exporting；Task结果execution_report|真实选择目录及文件；不复制完整报告到Task状态|

get_task及managed解包后的实际数据，先依据originating_operation选择新任务严格视图，再转换统一TaskState。新任务要求原请求ID和正确kind／结果；旧任务走原语义。不能让旧宽分支接受一个缺原请求ID的新操作结果。

此前draft7收紧ExecutionRequestStatus：registered分别用3个互斥分支关联operation与特定handle，另保留not_found。旧的独立operation枚举＋task联合会容许“start_execution_session配cloud_read任务”的结构；该错误配对现在应由schema拒绝。未找到原请求仍不授权自动重做外部副作用。

设备端仍使用stdlib窄wire解码，由开发期标准schema及样例对照；不因新增契约就给随包Python增加校验器依赖。

新操作仍沿用Request<O,P>，schema须按实际操作精化项目作用域；Host的实际作用域及权限检查继续保留。project_id显式null在原结构约定中允许，但没有Project的业务调用仍由Host拒绝，不能把结构通过当作准入。

公共schema生成可使用Rust操作元数据作必要精化，实际反序列化／typed decoder消费同一约束。单看生成目录新增了文件、编译能通过或154个名字齐全，都不足以证明原线上格式等价。

## 5. 26个结构样例及证明范围

SC01—22包含完整／缺字段封套、显式null项目、未知caller注入、原请求任务配对、可空字段省略、取令状态、独立采集分支、未探测遥测、安全整数边界及date-time正反例。值均用example-*身份，**不对应实际v1工程／设备／Task，也不是可运行验收夹具**。

两项样例故意区分结构与业务：SC03的显式null项目在结构上可接受，Host仍必须拒绝无实际作用域；SC16的expires早于issued可通过各字段基本类型，Host构造／发布必须拒绝。SC15的无probe原始遥测可按范围存云，不能更新Host设备资格。

每例都指向精确定义而非整个bundle根，预期与结果分列。标准校验profile为Draft2020-12元schema＋显式date-time断言，按各自文件URI注册本设计和get_run／get_task生成资源；关闭格式断言不能让SC22算通过。

先前bundle／工作区未找到标准工具的记录仅是历史发现。现已在独立.work工具目录使用jsonschema4.26.0及显式date-time断言：3份schema元检查、26个正反样例均符合预期，见[实际回执](../../.work/v2-design-schema-validation/receipt.json)。全部host_runtime_result仍为null；Rust生成及真实消费者未执行。

归属／引用／样例目标的核对属于文档层。160项行为设计预期仍全部未运行，本文件26例不增加或替代这些行为验收。实际v2生成契约验证、真实Rust往返／生成及Linux／Native／Agent消费仍待实施前后各自出口；v1验收优先，v2实施继续关闭。

预测来源、H10必填可空link、canonical／回执及比较状态精化见[预测比较设计](预测与执行比较设计.md)；ReportRunInputRef复用既有纯domain类型，RunId不作TaskId。

H11与H10共享exporting handle，原请求查询按4个操作分支关联3种handle形状；JSONL记录和必填可空分组起点见[筛选数据导出设计](筛选数据导出设计.md)。
