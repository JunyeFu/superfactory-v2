# v2.0数据查询与规模验收设计

2026-10-26。**仅设计；v1验收优先，v2实施门关闭。** [结构化设计](数据查询与规模验收设计.json)细化任务8的Q03，不减少百万数据、10路各1Hz持续30分钟、原始与分钟聚合各30次的要求。本轮未创建负载脚本、数据、服务或测试。

## 1. 任务链与本轮契约改动

验收者准备专用dataset和授权设备→导入可复算百万数据→从实际数据库导出原始前缀并独立形成预期→冻结60项查询→实测完整查询。10个独立采集进程另验实际节奏；它们不是10台生产执行设备，采集量不增加Engine接受量。

接口草案升至`sf.execution/2.0-draft11`，154定义。telemetry版`DaaSQueryResult`每页新增必填`dataset_id`、`selected_visible_frontier`，空页和末页也返回，避免只凭下一页游标推测读取范围。execution版原epoch/revision语义保持。新增纯domain `CloudTimestamp`统一这份新草案的14处date-time字段（含新数据导出元数据）；原v1生成schema和自由文本device_timestamp不改。

## 2. 时间、筛选和分钟口径

CloudTimestamp输入采用RFC3339子集：大写T；Z或已知数值offset；真实日历；本地及归一UTC后的年份0001—9999；秒00—59，小数0—6位；拒绝未知offset `-00:00`、闰秒及更高精度。输出固定UTC六位小数Z。Rust选择`chrono::DateTime<Utc>`作内部值，显式解析和序列化；TS为string，schema导出format及词法pattern。普通String、默认chrono序列化及正则自身都不能代替实际语义检查。

数据库使用`timestamptz(6)`。新TX04事件或TX10批次取得dataset锁、完成去重后，只采一次DB `clock_timestamp()`；一批共用此值。精确重试保留首次接收时间；cloud_received_at表示首次存储时点，不声称HTTP到达或提交完成时点。墙钟可能回拨，提交先后仍取ingress，不能用时间推断前沿。

C08遥测只取event_kind为telemetry/generated_load，排除receipt。筛选采用`received_from <= cloud_received_at < received_until`；相等返回空，反向422。解析为时间值后比较，offset等价输入归一UTC。device_ids排序去重，空数组表示所选dataset内已授权设备；显式越权403，已授权但无命中返回空。

分钟按UTC整分钟分组，仅输出非空组；稳定顺序为bucket_start、device_id、source_mode，row_index从0开始。发送方observed_at或device_timestamp不覆盖云接收时间；Host执行查询仍使用原单调毫秒及其既有时点范围，不套用云UTC窗口。

以上是所选产品规则。PostgreSQL的[时间类型](https://www.postgresql.org/docs/18/datatype-datetime.html)支持微秒精度，[时间函数](https://www.postgresql.org/docs/18/functions-datetime.html)区分实际墙钟和事务开始时间，且支持显式时区截断。[Chrono](https://docs.rs/chrono/0.4.45/chrono/struct.DateTime.html)提供解析、UTC转换及小数输出；所选更窄输入规则仍需wrapper落实。候选chrono0.4.45与[tokio-postgres0.7.18的with-chrono-0_4](https://docs.rs/tokio-postgres/0.7.18/tokio_postgres/index.html)仅写入设计，未安装或验证构建。

## 3. 固定前沿与批次重试

先捕获已提交F，再查询不可变事件`ingress_id<=F`，后续页保持dataset、规范筛选和F；原始行按ingress，分钟行按固定分组顺序。F是dataset提交前缀，不是筛选后条数。每页都回传dataset/F，消费者核对首个结果的选择，所有页读完才形成完整结果。

游标仍为不带签名的base64url JSON，不承担授权或首次签发真实性。服务端核对当前授权、dataset、筛选、位置及F不超过已提交前沿。合法授权前缀内改写F不等于越权，也不能宣称服务端能识别它是否原游标；消费者须拒绝一次查询中发生的选择漂移。本切片不增加签名、游标表或额外服务。

TX10一次原子保存1—1000行，ordinal为0至N−1。相同batch必须N、顺序、规范typed payload全部相同；精确重试返回inserted=0/reused=N，不重记时间或推进前沿。缩短、追加、重排、改内容均冲突。新batch撞既有dataset/device_ref/sequence时整批冲突，即使事件相同；不能用未存储的新batch身份返回全复用成功。现有DB08足够记录非空原子批次，无需新增批次表。

## 4. 百万生成输入与独立预期

使用TX13从统一部署配置预置的专用generated dataset，首次导入要求为空；设备G000—G099，批次batch-load-0000—0999。本切片没有另建dataset的API；重复计量复用原不可变百万输入和原batch身份，不追加另一份百万或宣称重新导入。改变输入需另行配置初始部署，不自动清库。对n=0至999999，定义d=n%100、device_sequence=n//100+1、device_ref=G{d:03d}、value=(d+device_sequence)%1000，metric=status_sample；批次n//1000，批内ordinal=n%1000。由此100设备各10000条，1000批各1000条。

observed_at固定为2026-01-01零时UTC加(sequence−1)秒，明确是**合成发送方时间**。百万导入可以很快，不能因此声称云端已有10000秒连续采集。

导入后停止对该generated dataset写入，从实际已提交dataset取得F0；验收者以只读方式导出DB08的F0内原始行和接收时间。未来verify_daas.py用Python标准库逐身份/字段对照生成公式，用身份位图识别缺失和重复，再独立计算UTC窗口/分钟预期；不以C08或被测SQL聚合作自己的答案。普通数据读者不获得数据库权限，导出不包含连接秘密。

正确性检查须逐一覆盖百万身份、内容、所有原始API页和全量分钟聚合。只看总数会漏掉“一条重复抵掉一条缺失”；不新增校验和或无消费者血缘层。

## 5. 60项固定查询与计时

先基于原始导出确定查询清单和预期，再开始任何正式计时，不按性能结果挑窗口。区间端点精确到微秒。时间相同的并列行全部保留，不能裁剪到计划名义行数。

|组|j=0至29的固定配方|独立预期|
|---|---|---|
|原始30次|设备G{j:03d}的10000行按接收时间/ingress排序，取含首尾排名1000+10j至1099+10j的时间范围；上界为末时点+1微秒|从原始导出重新筛选该设备和半开窗口，结果按ingress；时间并列可能多于100行|
|分钟聚合30次|全部100设备的百万行按接收时间/ingress排序，取含首尾排名10000j至999999−10000j的时间范围；上界+1微秒|独立筛选、按UTC分钟/设备/来源计数；名义覆盖100万至42万行，包含并列|

使用page.limit=200。先各做一次有标记的固定warmup，随后依次R00、A00、R01、A01至R29、A29；逻辑查询串行，不逐例预热或人为清缓存。正式样本均保留。

每次计时从首HTTP请求实际开始到最后一页读取并解码完成，包含连接、排队、网络及分页；独立预期已提前算好，对照耗时另记。正确结果、完整全部页和选择一致才构成有效查询。两组分别取nearest-rank p95，即排序30个耗时的第29项，目标均≤2秒；任何报错、缺页、缺样本或内容错误都不能删掉后宣称整组通过。百万全量下载的正确性检查与这60项性能样本分别记录。

这组测量是API查询性能。设备发送到正确呈现帧仍按原Q04固定100样本和同钟/保守上界取证，不能从API耗时推导画面已更新。

## 6. 10路各1Hz持续30分钟

10个独立telemetry_only进程使用各自boot和设备序号，独立于生产执行及generated dataset。预检/热身结束后各自建立单调锚点，seq1—1800；每个[k,k+1)秒槽内实际创建一条新采样并开始首次请求，运行覆盖至少1800秒。记录实际创建、首次发送、重试和ack时点，不用计划到期时点冒充实际发生。

每轮使用新的10个进程boot；合计18000个唯一事件、各进程1800个槽、原始数据库对应关系及实际采样/发送节奏一起验。数据库成员核对限定本轮10个boot和seq1—1800，不能拿包含历史轮次的dataset总量作本轮分母。重试保持原身份和内容；中断后突发补齐数量不能修复已错过的连续采集槽。UTC分钟边界与网络抖动会影响每分钟入库数，不能强制每个云端分钟恰好60条。

百万dataset先导入并静置，查询可安排在预先选定的30分钟采集区间内；记录真正重叠的时间。未发生的重叠不算并发证据，未完成的30分钟不算完整采集。
