# 运输路径、共享通道与目的接收

范围：**后续储备设计，当前首版不实现复杂路径、交通与候车**。首版按[交付基线](../00_项目基线/首版交付基线.md)及[S01-01产品边界](../00_项目基线/用户任务与产品边界.md)执行；本页保留该扩展的设计，不作为当前首版能力声明。
状态：业务设计。复用transport/resources/templates和共同时钟，不增加常态画布。路线是物流条件，画面箭头既可表达概念供应，也可投影实际声明路径，两种含义分别标注。

## 用户怎样从连线做到可彩排运输

|动作|必要决定|系统处理及看到的结果|
|---|---|---|
|连来源和目的|物品、单位、批量、库位、接收条件|按ID连接现有对象，连线本身不创造运输设备|
|选运输方式|小车/人工批次、声明输送或专业运动；时间或路径模式|明确支持子集；不能把同一小车规则套到机械臂和连续输送|
|配置位置与路线|停放点、取货点、送货点、可行方向及等待/装卸位置|显示空驶、载货、返程；路径长度来自认可的连接，不从镜头计算|
|配置共享约束|车辆/人员、通道冲突区、候车位容量和日历|点占用显示任务、方向和下一已声明事件|
|移动设备/线组|接入点如何随新位置接到原通路|保留内部ID；显示变化的路径、断开的接入段及运输时间|
|查看运输|选批次/车辆或时间轴|来源预留、装载、在途、抵达待接收、移交、空驶分别显示|

物理车辆所在位置、逻辑货物持有者和目标库位是不同字段。车辆空着不代表在新取货点；货物到门口不代表库位已经接受。已有固定时间样例保持原输入，未给定地理路径的厂际供应仍使用声明时间。

## 坐标与两种模式

设备/端口以厂房和线组局部坐标保存，按布局变换得到共同厂房坐标；同一计算供画布、包络和物流使用。移动整线是布局改变，不只是镜头变换。内部相对位置和对象ID保持，成员库存不复制。

**fixed_time：**装载、去程、卸载、返程或空驶分别声明时长。布局变动后仍采用原时间，但指出这些值尚未因距离更新；不能宣传移动后更快或自动缩短。

**explicit_path：**有向节点/边、米制长度、接入点、允许方向与声明速度。用户认可路线或使用实际已实现的路线工具；找不到合法连接时标不可达/待重接，不退化成穿墙直线。各边名义时间t_e=L_e/v_e，另加装卸与等待；未输入加速、拥堵或转弯特性时不自动计算。

不同厂房的局部原点不自动是同一地理坐标；多厂房供应线默认概念关系。只有声明的厂际道路/时长进入运输，不从多厂房卡片间屏幕距离计算公里或每天到货数。3D几何、净空、车辆运动学和实际交通许可需专业输入，本模型的逻辑通道容量不是它们的替代品。

## 车辆不能瞬移，货物不能重复领用

默认完整任务：可调度需求→选择车辆与角色→必要空驶到取货点→装载预留→实际发出→沿路线移动→抵达/等待→卸载接受→声明返程或在目的点待命。来源物品真正发出前仍在源库位且被预留；发出后唯一持有者为运输任务/车辆。

共享车辆转接另一条供货线时，下一取货点与车辆当前位置不同，就必须有空驶路径或声明空驶时长。策略可选择return_origin或stay_at_destination；旧样例继续return_origin。选择后者不代表下一次任务立即开始，还要核对空驶、日历、角色和发运窗口。

装载、移动、卸载各自声明资源阶段。离班司机不能被新取得；允许无人移动也需行为明示，不能由AGV插图判断。已知不可中断边的完整用时必须落在所需资源可用区间内；不足则留在合法等待点，带货不消失。搬运容量按物品/容器及规则计算，不能将不同零件件数简单合计为载重。

## 共享通道按真实占用条件推进

路径边关联冲突区/道路资源；可双向但单车的狭窄区由同一容量1资源管理，不能给两个方向各复制一份。车辆进入下个区间前，要取得它需要的共享区和目的安全等待位置；离开源等待位置后释放原位置。到下一安全位置，才按规则释放上一共享区。

连接多个边的通道可以声明一个完整互斥区，持续到下一安全位置；也可有多个明确区及等待点。范围与容量由设计者输入，不推断实际防撞能力。两个任务争用按就绪时间、再实例ID选择；“空车返程”仍占同一通道，不给它隐形穿越权。

目的库位容量与车辆停车/候车位是两层。若有区外候车位，抵达后可以释放狭窄通道，再保持货物等待接收；若没有，车辆仍占通道，后续运输也等待。画布应明确显示停在哪里，不能把“在库位门口等”画在通道外而调度仍占路。

节点相互等待时显示具体占用链：A持有P1等待P2，B持有P2等待P1。没有后续释放事件时说明“当前安排无可推进事件”；用户改等待位/方向/调度后重跑。不能从循环等待自动宣布有最优重排，也不能为了继续动画瞬移或复制位置。

## 接受不是抵达，返程不是接受

目的接收空间在卸载开始时预留，卸载完成时提交一次移交；在此之前货物仍属车辆。质量/版本/订单接受等其他条件照原规则检查，预留位置不代表已经放行。材料接收与车辆空驶完成独立：收到后下游可开工，车辆按实际位置与日历接下一任务。

临时改目的地、取消未发出任务或中止在途是不同业务。未发出可以释放预留；在途必须选择认可目的/退回路径，不能直接恢复源库存。该扩展按新方案中的明确运输任务表达，不声称已提供运行内人工改派。

## 支持的设备类型怎样接入

|类型|本次共同规则|额外专业条件|
|---|---|---|
|小车/人工搬运/叉车示意|批次、空驶、装卸、路线、角色、通道、接收、返程|载重/包络与实际操作条件；不由模型外形获得|
|AGV示意|同样的声明任务，可明示无人移动阶段|实际导航、定位、避障和调度协议不默认支持|
|传送设备|声明固定转移时间、容量与接收条件；固定布置|连续间距/累积、速度段、转接控制需对应规则|
|机械臂/升降/专业转运|消费认可动作、阶段资源和移交事件|真实轨迹、可达、碰撞、载荷等由专业成果提供|

不因都能画箭头就承诺具备相同运动机制。第一组可完成通用方案彩排，专业组继续按已有41方向的接入设计深化。

## 贯通预期与图面

自建例2秒装载、1m/s、3秒卸载。认可10m路径：15秒接受，25秒返回；搬到认可20m路径：25秒接受，45秒返回。固定时长模式移动后仍15/25秒，并注明时间未重估。车辆若先空驶5m，则再增加5秒。

双向8m共享区，两车2秒同时就绪：A先过2—10，B10—18；接受13/21秒。空车仍争用通道，A18—26返回，B26—34返回。接收满时区外候车能释放道路，但仍占车辆；无区外位会拖住后车。详见[路径与维修预期](../../scenarios/路径与维修/README.md)。

这些是自建名义输入，没有实测速度、车辆交通或工业收益。详情/覆盖层/底部时间轴承担编辑与解释；常态画布仍只有流水线和多厂房。
