# 建设、投用与生产时间边界

范围：**后续储备设计，当前首版不实现建设与投用条件**。首版按[交付基线](../00_项目基线/首版交付基线.md)及[S01-01产品边界](../00_项目基线/用户任务与产品边界.md)执行；本页保留该扩展的设计，不作为当前首版能力声明。
状态：真实业务设计。任务服务工厂新建、局部改造或设备替换方案，沿用两画布和共同工程；没有实施现场验收或真实设备控制。

## 人要确认的四件事

1. **设计成果可用于什么**：厂房/设备/柜体/程序的版本和认可范围；一张认可图纸并不使设备成为可运行资源。
2. **哪些工作先后发生**：到货、安装、接线、管路、软件配置、联调、首件或其他投用前置；依赖可以串联或并行。
3. **怎样判断可用**：任务完成证据、专业条件和采用决定各自明确。预计日期可作模拟假设，日期过去本身不产生合格决定。
4. **从哪天比较生产**：计划生产起点、工作日历、订单交期和观察窗；投用延期是否落入原窗口应可见。

方案阶段可以声明投用事件进行比较。决定来源为自建预设、企业提供、实际专业工具或人工认可，工程包中保留来源与范围；未知决定显示待确认，不把施工图认可、虚拟联调和现场投用写成同一状态。

## 投用对象与依赖

投用包属于模板/人工任务/专业模块的组合，最少包含target_ref、required_artifacts、construction_tasks、required_services、readiness_conditions、planned_release_at和release_decision。设备、线组、厂房都可作为目标，线组依赖其必要成员与公共服务，不能用一台设备完成代替整条线。

|对象|前置与交付|对生产的作用|
|---|---|---|
|场地/厂房|认可位置、空间、相关建设任务及投用条件|在目标厂房不能使用时，成员作业等待；布局草稿仍可编辑|
|固定设备|到货、安装、所用作业与服务、联调和声明投用决定|决定资源可用于哪个工艺/模式、从何时可用|
|控制柜/程序|认可连接/信号、安装接线、软件配置和受支持联调|产生设备投用前置，不是每件产品经过的工位|
|工装/专业准备|工具、夹具、板位、原生Job、首件等条件|按目标产品和配置约束开工，不能只看设备是否有空|
|公用工程|连接点、可用时段、容量与品质边界|运行阶段还需持续满足服务需求，不是一次勾选永久可用|

没有声明建设包的旧工厂样例继续按其明确假设提供初始可用资源。本轮新增可选投用约束，不反向给所有演示补一套虚构施工成本。

## 时间怎样连接

工程有一个日历参考起点，建设里程碑和生产方案都映射到它。用户选定生产观察起点t0后，ready_at相对生产时间为绝对投用时刻减t0；早于t0的目标可以作为初始已可用，晚于t0则在运行中等待。显示可以按建设日/生产秒切换，但不能创建两套互不对应的时钟。

建设任务的计划日历跨度不等于工作人员连续工作小时。施工人员日历、承包工作量、费用未知时只显示里程碑，不从“3天安装”推导72小时人工费。生产资源仍按各自实际声明班次运行；阶段已支持的中断规则继续适用。

同一方案比较保留生产起点和交期。投用延期不能自动把订单日期一起往后移动，改变观察窗也须列入比较条件。窗口结束未能生产时显示未交量与预计投用事件，完整订单时刻为空。

## 投用决定的状态

草稿→待前置→待认可→在声明范围内可用。安装结束只改变相应任务；所有需要条件和决定具备，才开放目标运行。某专业成果版本改变时，检查受影响的投用绑定和作业，不能全局删除所有旧成果。

改造进行期间，旧设备是否继续服务由方案明确安排：parallel_install、shutdown_window或replacement三种业务策略。替换设备时保持产品/订单定义，但资源、端口、路线和在制交接需要显式决定；没有迁移规则不把旧设备在制直接搬到新机继续。

真实业务中需要维护、复验或重新标定时，用相应任务关闭并重新开放指定能力；不因“维护结束时间到了”自动宣称精度恢复。该扩展的初始范围是明确日历与预设决定，真实现场采集和运行内改造另行实现。

## 界面、交付与完整例子

选中设备/线组→投用面板列前置、计划日期、证据范围和未满足项→时间轴显示建设/准备及生产观察窗→点等待定位未到柜体、未认可程序或未满足服务。两画布状态相同，投用面板不是第三张画布。

[投用与专业案例](../../scenarios/投用与专业接入/README.md)使用建设D0、生产D4 08:00：基线D3 12:00具备条件；柜体延期使投用变为D6 12:00。原24小时窗口内后一方案没有产品，不把它挪到投用后再宣称交付相同；扩展窗口才得到53小时10分的完整时刻。

设计包交付任务依赖、认可成果版本、投用决定范围、共同日历/生产起点、服务绑定和未确认项。软件在环通过只能证明所运行软件与模拟对象的对应行为，不能作为现场安装、安全或实际工艺质量验收。
