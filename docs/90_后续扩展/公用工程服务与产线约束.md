# 公用工程服务如何约束生产

范围：**后续储备设计，当前首版不实现公用服务容量与专业网络求解**。首版按[交付基线](../00_项目基线/首版交付基线.md)及[S01-01产品边界](../00_项目基线/用户任务与产品边界.md)执行；本页保留该扩展的设计，不作为当前首版能力声明。
状态：设计。该扩展的首个实现拟支持声明容量与条件，专业电网、气站、热流体求解仍有独立范围。电/热/冷/气/水作为服务资源绑定到设备阶段，不用离散物品件数表示，不新增一种库存。

## 同一设备有物品流也有服务需求

物品端口负责毛坯、部件、产品、包装等实物归属；信号端口表达状态；专业成果负责认可作业。service_binding单独声明设备/阶段使用的服务资源与连接点，沿用现有resources和professional分类。服务网络不是第四张常态画布；在两画布上按需显示公共设施和连接覆盖层。

|服务|可使用的声明量|还要明确的条件|
|---|---|---|
|电|active_power_kw，或独立的apparent_power_kva|电制/接口及认可边界；kW和kVA不自动相加换算|
|压缩气|同一参考条件下的flow_lps等体积流率|参考温压、表压/绝压类型、所需品质；额定流量不推导用气点压力|
|冷/热|cooling_kw/heating_kw或专业定义流量|工况温度、换热/供回边界；不从热图推算服务能力|
|水|flow_lps及合法专业组分/品质要求|入口、出水去向和适用工艺；水流不当零件计数|

数量、单位和参考条件必须明确。兼容条件只接受用户声明或实际专业输出；没有压力/质量计算时仅报告声明容量范围，不宣称整套站网合格。DOE资料作为系统/末端需求的技术依据，历史资料日期与阅读范围独立记录。

## 需求和容量的计算

节点v的可用容量C_v(t)，固定背景用量B_v(t)，作业阶段增量需求d_j,v(t)，按同单位要求B_v(t)+Σd_j,v(t)≤C_v(t)。背景与增量分开，否则会把机器同一待机耗电算两次。不同单位或气体参考条件不一致时不进入同一个和式。

每个绑定点保存source_ref、connection_ref、quantity_kind、unit、reference_conditions、demand_basis、required_properties及受影响阶段。共享上级电源/气源时同时满足上级和分支容量，不能给两个子厂房各复制一整份公共容量。该扩展的初始范围是明确的树状/共享约束，不解任意电路潮流或管网压降。

开工时共同取得完整物品、设备/人员及全部当前阶段服务；缺一项就等待，不先占电再无限等气。未绑定服务的旧样例显示“未建模”，不凭此宣传服务充足。与用户已选择的量化结论无关的服务缺项不阻止布局编辑。

## 阶段和供给变化

需求按阶段进入与释放，不以图片亮灯时长决定。待机背景需求另定义；暂停或故障状态采用自己声明值，不能默认沿用加工峰值。等待不会产生有效加工进度。

同时间先累计上个区间的进度和完成，再处理到料/投用/容量更新，最后尝试新开工。区间为左闭右开，恰在容量变化时完成的上一阶段可以提交；之后的新阶段采用新容量。

服务中断必须有工艺规则：pause_resume保留物品/机器和有效进度，释放不需持有的服务/人员，恢复后重新取得全部阶段条件；abort_to_isolation转声明隔离并等待处置；不可中断且未定义处置则该扰动情景不可执行。不是所有真实加工都能暂停后继续。

投用允许开工不意味着未来服务不会中断。供给时间曲线可以来自声明计划或实际专业结果；不能把专业软件的计算墙钟耗时当生产停机时长。

## 已知负担怎样说清楚

本例两机各用6kW与2L/s，持续30秒；公共上限10kW/3L/s。先后做60秒；只增电到14kW或只增气到5L/s仍60秒；两项都增才可并行30秒。待机为0，仅两台声明负载，能耗两方案都0.1kWh，用气都120L；更快不等于更省能源。

这些是自建容量约束，不是电网/管网工业实证。扩容设备、费用和现场许可均未取得，不借本例评估投资回报。若要求用气点压力保证，必须另有受支持气站网结果与边界，不能使用上限表替代。

## 看见等待及接手

点服务绑定显示背景、阶段增量、容量、参考条件及谁正在使用；点等待显示具体电/气/水/冷源和未满足条件。整厂/跨厂汇总按同一源累计，不重复成员负载。物品库存、服务占用与实际消耗分列。

交付所用配置、需求曲线、专业成果版本、求解范围和未建模部分。加入气站/热冷/电热模块时更新服务能力与品质条件，工厂消费该结果；不把专业工程的预测节能与同一次排程改进再加成两份收益。
