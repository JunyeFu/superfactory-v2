# P3-04 原生产品捕获基础层完整续作

继续[P3-04原完整包](P3-04_整包执行.json)与[完整生产者核定](../../../scenarios/Agent共建/runtime-render-view-source-review/source-review.md)。全部原九视图、Task/权限/取消/managed资产、GF/IX/NFR/release保留。Root选定同源RenderSurface与WebView2 CapturePreview，不采用外部截图、CDP或替代viewer；真实隐藏窗口捕获仍为下一硬门，不可从官方API存在推定成功。

本代理完整负责Native捕获基础层：新 `apps/planner/src-tauri/src/native_render_capture.rs`，提供可信Rust调用者传入真实产品WebviewWindow后的异步CapturePreview到内存PNG结果；COM/流留原UI STA线程，完成后仅Vec<u8>/错误跨线程，不持Host mutex、不阻塞UI等自己，不接外部PNG/路径/URL/caller/window-label字符串。复用锁中webview2-com0.39.1/windows0.62.2，禁止混windows-sys COM类型；错误明确返回，无静默空图、重试、sleep就绪或默认图。

窗口建立、冻结数据/资产读取与真实frame-ready由后继可信Native/RenderSurface集成负责；该基础层只接受实际Native对象，不放宽main-only读权。CaptureOnly的隐藏HWND/controller可绘制状态、无焦点变化和相机变化实际PNG，由Root实际Native生命周期验证；基础层不得自行显示main或拿外部屏幕截图顶替。

当前持久化展示槽代理独占Cargo/生成器。先写上述新叶源及 `scenarios/Agent共建/runtime-native-capture/` 的必要编译/调用交接，不改lib.rs/project_api.rs/main.tsx/原任务JSON或其它活动源；Cargo暂不运行。等Root明确释放Cargo后，才可在原Native Cargo.toml/Cargo.lock加入锁中既有Windows target直接依赖并做必要编译验证，不安装/升级库。若需临时编译入口，可用本目录独立harness调用同一叶源，不能复制捕获实现；Root后接正式mod与实际产品路由。

Root已原则批准后继RenderViewParams可省略module_ref与comparison原CompareRunsParams两个精确选择载体，以及私有allow_view_control显示授权，均待公共类型单写期结束后统一落地生成，本代理现在不写API/Host权限源。ShowAndCapture选用同一产品任务视图窗口并显式授权显示；scene_revision用实际挂载ScopeR，ProjectR单独保留。其余逐kind条件沿九视图矩阵，包装preview的精确样本选择仍需据真实类型收口，不猜phase/sample index。

完整基础层代码、自审、精确依赖/编译回执与真实运行的未完成项一次交Root；不得停在另一份方案，不把编译当Native捕获或整包完成。Native启动、GUI及最终第一张真实产品PNG仍由Root独占执行，后续同Host完整接线继续原包。
