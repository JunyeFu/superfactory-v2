## 设备建模提速复盘与默认执行方式（2026-10-26）

用户明确允许损失少量几何精准度换取明显效率提升。新批默认采用`simulation-efficient-v1`。此调整作用于设备可视建模与资产接收方法；真实业务、持久化、权限和原正式NFR要求保持。建模精度按[统一规范的效率优先规则](../02_交互设计/设备建模精度与表现验收规范.md#效率优先的可视仿真建模2026-10-26)执行。

Q15只接收1种设备，复审目录已有28个JSON，且经历4轮Native拍摄、4次普通Native启动和反复源包重建；详细设备1150节点/27.61MB，纸坯2057网格。该数据来自当前文件，不是同复杂度前后耗时基准。主要问题在执行失控：把3µm、ppm纸量和逐根管路校核自行升级为门槛；在布局未稳定时做细节和全套留证；晚查暂存/缓冲重叠；每台复制一套脚本，变成串行从零制作。原工作流已经要求最小验证与复用，并未要求这些微观数值。

进一步反思：慢的不只是导出，而是把可视仿真当成机械设计求解，又把每个局部修正重新包装成一轮完整接收。只减少网格、不改变这些决策，仍会很慢。Q16、Q17已分别整批接收3种，说明家族复用可用；现有记录尚不足以证明整流程提速倍数。

**先分配精力，再动手。** 身份、物料数量/来源、质量路由、holder、时钟和保存必须准确；轮廓、主要材质、关键执行头、支承与物料变化必须看得懂；螺纹、隐藏内构、细小配合及材料连续变形允许近似或省略。几何判断先看实际正常视距和必要机构近景；无可见问题、无业务影响时，不先推导容差公式或增加碰撞求解。薄纸/胶带可用贴花、薄片和状态网格，实际消耗仍取业务数据。

以后按以下五步推进：

1. **定义并归家族**：先明确输入/输出、身份变化、关键动作、端口、工件尺寸、私有暂存与输出缓冲。优先纸包装；共享机构及业务规则的3–5种组成一批，不只因同属纸包装就混批。优先沿用已有接收模板；一种新质量/返工语义先单独走通，不让复杂分支占住其余成熟设备。定义和验收仍逐设备。
2. **先做空间业务闭环**：复用最近通过批的机架、材质、导出与Host/Native入口，只写设备差异。以开始制作后10–15分钟内看到第一版粗动作作为推进提示；工具链可用就先出图，不在首次预览前展开完整机械推导。用粗装配先走上料→加工→卸料→输出阻塞→恢复，检查工件支承、工具行程和两个输出位置分离。冻结前同时查看代表工件的完成态近景，确认声明的成品变化确实发生，例如沿内壁折入而不只水平折边；使用现有组件图，不另加一套报告。此阶段不做螺纹、内部流道、精细折痕、全量截图或源重建。
3. **代表机补外观，再出变体**：代表机机构可解释后，再补同族尺寸、执行头和独立业务定义。简单平移/转动先用起止姿态及阶段边界；折合先用刚性板片，需要弯曲才分8–12段，不为凑16–33个采样给每条通道加帧。抓取、压合、封箱等允许有依据的分段动作与工件状态切换，不必模拟连续材料力学、真实控制器或每根随动管线。主要安装、驱动和可见连接必须保留。
4. **冻结后一次验收**：真实导出重开、每设备MQ八项、自动七向图及必要近景；每设备真实Host覆盖适用工况，批内共享一个Native进程捕获约6–8个有区别状态/设备，并用实际状态读回验证恢复。一个普通界面保存和一个新进程重开覆盖整批及所有当前资产。镜头不对只重拍镜头；改一台只重验它和实际受影响部分。
5. **整批收口一次**：一份批级复审结论引用已有原生结果，更新正式登记、图册和对应Todo。无新失败后停止加码。未完成的设备不计数，但不阻塞同批已独立通过的设备。

已做一项不修改已接收资产的有限试算：同一Q15纸坯配方、101个姿态，64段改8段后纸材子网格估计由2057降至265（约减87%），最大体积近似误差约0.0107%；本机该数学检查平均65.4ms降至9.5ms。结果见`.work/native500-quality-20261025/workflow-efficiency-check.json`。这只证明该局部算法的取舍，不是整机导出/Native或批次提速测量。

默认不再要求：微米级全机配合、ppm网格体积、每根线/封闭内构、全网格逐对连续SAT、千级关键帧、每次细节改动完整重建/保存重开、固定28张或更多Native图。精细检测仅用于任务明确要求或粗检查发现的具体局部，修好后撤出默认路径；旧批的44/53/126等采样数不继承为新批门槛。

单个非关键细节投入约5分钟或一次局部修正后仍无可见/业务收益时，立即改用封闭总成、共享材质或较粗几何继续，不再沿同一路径精修。已观察到的缺支撑、可见穿插或错误成品必须修好，可更换机构表示方法，不能填通过。时间数值是调整表示方法的提示，不是接收超时或新的计时门槛；不因此停下来请求确认。

每批只维护已有生成源、实际结果及一份复审结论，不为一张图、一个修正或一个运行时点另造规则/报告。冻结前便宜检查可反复；冻结后只重验真实受影响部分。以真实接收种类的单台平均耗时评估改进，不以候选生成数、截图数或日志数计算产能；已有批级结果记录批用时/已接收种类即可，不另建统计平台，也不在实跑前承诺固定提速倍数。

## 当前版验收与下一版设计

当前v1.0仍按原逐包计划、原执行JSON和剩余Todo完成验收；v2.0按[开发控制设计](../06_v2.0设计与开发控制/开发控制设计.md)及[控制计划](../06_v2.0设计与开发控制/开发控制计划.json)仅整理需求、六视图、文件接点和前置。下一版设计完成不代表当前版验收完成，也不授权实施下一版。

v1适用出口实际接收前，不把v2源码、接口空壳、新依赖、版本号或部署混入当前候选；v1真实缺陷修复仍按原范围推进。下一版不增加v1验收门槛，不把三材料就绪代替原技术验收。版本切换时先按v1最终源码重定位设计接点，依当时有效指令启动，不由设计队列自动开工。

## 从搭建到交付

1. 明确本轮用户任务、完成标准和现成资产；沿用已有架构、接口、依赖与授权。新项目先做一个可运行纵向业务闭环；已有项目直接定位当前缺口，不重做脚手架或阶段准入。
2. 只补实现者必须知道的输入输出、状态归属、单位、异常结果和消费者；无需求不增加接口层、配置、日志或未来扩展点。依赖安装、端口和共享写入仅在实际需要时检查。
3. 从原包选一个能闭环的动作：原输入/预期→实现或修复→必要验证→实际消费者。独立预期来自契约，不按结果改答案。实施前置取实际产物，正式关闭仍取原完整出口。
4. 消费有效证据，完成当前包的剩余适用出口；发现阻塞生产者由统筹处理。获准并行时仅派给空闲窗口、固定独立输入/写范围、无必须通信的完整任务，执行中不打断；共享Native只由一个操作者持有。
5. 固定交付候选后执行尚缺的正式验收及材料对应检查。原需的性能/并发/持久化检查不降低；第二机、真实指定客户端授权、逐素材权利确认等已取消条件不恢复。人工签认、公开访问和发布如实分开记录。

## 测试力度

|本次改动|最小充分验证|何时加深|

|前端类型/交互|类型检查；存在有意义行为测试时运行对应文件；视觉/焦点/指针结果由真实Native驱动、截图及生产状态读回验证|Host持久化、原生路径/关闭或呈现帧相关时使用实际Native及对应受限夹具/事件和帧采集；组件检查不冒充它们|

区分两张清单：本次改动需要重验哪些行为；整包还缺哪些原验收证据。前者通过即可结束本次修改，后者随当前包收口，不重复修代码或把全部未验项挂到每次小改上。通过编译只证明编译；静态/Host/浏览器/普通Native/正式性能/人工各保留其证据层次。

原NFR的1800次时延、48个FPS窗口、40次保存打开等矩阵仍按原要求执行；不为本次文档修改启动它们。性能采样前先满足原环境条件，不反复在不合规画布上尝试采样。

## 底层执行入口

`tools/dev/verify.mjs`包装已有Node、typecheck、Cargo入口，默认只列命令；`--run`才执行。它不安装依赖、不启动Native、不生成新候选、不重写验收预期或任务状态。任务自身有专用Host/场景入口时优先使用它，不必再套一层。

```powershell
# 文档：只读取明确文件并解析JSON
node tools/dev/verify.mjs --kind docs --file docs/04_开发与验收/剩余任务Todo.json --run
# 单个既有Node行为测试；路径由当前缺口确定
node tools/dev/verify.mjs --kind node --test tools/dev/verify.test.mjs --run
# 前端：先类型检查，再执行显式给定的行为测试（如有）
node tools/dev/verify.mjs --kind frontend --test tests/planner/workspace-refresh/refresh-order.test.mjs
# Rust：显式包与筛选，不默认全workspace；去掉filter才运行该包全部测试
node tools/dev/verify.mjs --kind rust --package sf-domain --filter TEST_NAME
```

后两例是查看执行计划，实际测试时将路径/筛选替换为当前任务的有效入口再加`--run`。已有全量`npm run test:rust`和`tools/s07/verify.ps1`保留，分别用于明确需要的全量回归/工程准入，不作每次续接默认动作。

运行失败就处理实际失败，复验受影响部分；通过后停止加码。缺测试可用直接行为观察验证，不能为了满足“有测试”写只检查实现字符串、标题或行数的测试。工具退出码必须保留，未运行不写通过。

## 记录、候选与清理

- 本轮结果写对应原执行JSON的现有动作/结果字段，标明实际候选、输入、预期和结果引用。可读MD只同步受影响的契约/摘要，不复制全部历史；阶段进度由该结果汇总。
- 当前焦点、待确认动作和现场从计划/Todo/检查点读取，不把百分比、PID、窗口标题与每轮状态追加进AGENTS。新规则窄改原段，历史记录归档后只按需读取。
- 不变的验证内核/契约可以复用；若正式协议限定同候选，局部复用不自动关闭该正式组。证据匹配按实际差异和消费者判断，无需为内部对象新增全量hash或血缘层。
- 同一候选复用现有target、依赖和测试工程；独立窗口仅建立必要隔离副本。发布闭包只含实际源码/资源/依赖，不收编译缓存、历史工作副本或调试输出。已保留验收证据不重复大文件复制。
- 仅在接续Native、切换候选或桌面验证收尾时核对实际超级工厂窗口；纯文档/局部代码检查不操作桌面。已保存、无活动任务及未提交表单的过期窗口正常关闭；不确定草稿先保留，必要时独立保存核对。按实时PID/可执行路径枚举可见且无owner的`Tauri Window`，不能直接以`MainWindowHandle`选关闭目标：`Tao Thread Event Target`也可能可见，误关会破坏事件桥。正常关闭仍经生产保护；以OS进程退出核验结果，WebView2缺少`Page.close`事件不能单独判为产品失败。不得用旧PID/同名标题批量强杀，不删除旧Run或原工程。
- 技能、全局配置、记忆及产品源码各自保留边界；本次更新不写记忆，不自动提交或推送全局技能。外部动作沿用明确授权，缺授权时先准备可审阅成果。
