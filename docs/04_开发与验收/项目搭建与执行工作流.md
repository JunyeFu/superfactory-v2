## 设备建模提速复盘与默认执行方式（2026-10-27落实修订）

用户允许损失少量精准度换取大效率提升。继续使用`simulation-efficient-v1`和[建模统一规范](../02_交互设计/设备建模精度与表现验收规范.md#效率优先的可视仿真建模2026-10-26)，直接改变制作与检查范围，不增加任务层、评分、审批和过程报告。

### 为什么体系化后仍然变慢

流程已经允许近似，但执行和脚本没有同时减负；责任在实施取舍。早期“生成候选”与现在“正式接收”也不是同一口径，不能据此编造整体速度倍数。

|已核实的成本|纠正|
|---|---|
|小细节仍按机械制造推导；在制Q22为固定取放路径实现了六轴/SCARA逆解和精确伸缩级连接|固定示例路径默认烘焙关键姿态，抓放点对齐、关节连续、工件随工具即可；不默认实现通用IK、完整碰撞或真实传动。现有正确代码直接保留|
|上一版只删了重复近景，仍把逐设备Host全部工况在Native和两个普通进程再走一遍|逐设备Host检查保留；Native每台保留正常和输出阻塞，同族共享的三类等待采用代表机。新增机构/绑定仍独立检查|
|Q21的5种设备仍拍25帧Native，两普通进程各读回70时点；每批还复制prepare/verify等夹具|成熟家族复用原参数化夹具，只补输入差异；Native选择范围直接驱动拍摄和保存读回，不再只在文档里建议少验|
|一处几何改动牵动冻结、整批再导出、保存重开及汇总；可继续放大就继续修|外观稳定再一次冻结；只重验受影响设备/包。定义、主轮廓、材质和关键动作可辨即结束，不追加微观优化|

上表是实际成本和取舍，不是端到端计时结果。以5台**满足同族复用条件**、每台5种标准工况为例：Native由25帧减为13帧（每台正常/输出阻塞10帧＋代表机其余3帧，减少48%）；普通进程各从70时点减至34时点（减少约51%）。特殊工况另计。Q21历史结果保留，不追认其全部设备已满足同族复用条件；上述比例是检查量计算，不是实测建模提速。另查Q21普通进程原始回执：70个观察点只有34个独立时点；同进程按时点复用整份只读状态可减少36次重复查询，观察点不删。这与选择工况是两项优化，不叠加声称总体提速倍数。

### 精准度花在哪里

- **保留**：独立设备定义、规格/数量/来源、质量路由、holder、时钟、等待恢复和当前资产保存；完整可旋转3D、L03整体轮廓/材质、主要支承、主工作头与成品特征。
- **默认近似**：曲面/倒角/小紧固件用共享件和材质；线束成束或简化随动；封闭传动用总成；纸层/孔壁/胶层/订丝用纹理、重复件或前后状态。允许近景看出次要几何近似。
- **固定路径动作**：预设少量关键姿态并插值；取件、放件、暂停和移交点正确，持有段工件绑定工具。中段轨迹允许工程示意的平滑近似，不求机械最优轨迹、逐轴真实加减速或制造公差。只有任务确需任意目标规划时才实现IK/规划器；预设路径不宣称具备该能力。
- **停止条件**：正常产线视距及单设备完整视图已能理解设备、主要动作和成品；默认一张机构近景足够。非关键细节最多一次局部修正，无明显收益立即采用简单表示。明显悬空、主机构断开、工件明显穿透/丢失/复制、错成品、错误业务和材质丢失仍须修。接地/支承按实际画面及MQ接触结论判断，保留间隙数值诊断，不以固定1mm微观间隙卡接收；新批拍摄钩子不再复制旧数值拒绝条件。已有正确结构不为简化而拆除。

### 默认五步

1. **选族并写差异**：成熟机构每批参考6–10种，新机构先1–2种代表机；复用工具、机架、材质、动画总成、导出和原夹具。不为批号复制包装脚本，不先建设新平台。
2. **先跑粗动作**：工具现成时约10–15分钟先看到上料→加工→卸料、成品与暂存。一次动作先用一个主总成，先抓放/交接，再补关节与外观。时间只提示换方法，不是伪填通过的理由。
3. **补到观察尺度**：代表机达到轮廓、材料和关键机构清楚，即生产变体。每台仍实际复核MQ八维度、双LOD七向拼图、主要接触和阶段/反向seek；七向图由共享脚本自动生成，不逐图写重复结论。
4. **冻结一次、按下表验收**：每设备全部适用Host工况；每设备Native正常/输出阻塞；符合条件的三类等待由代表机验。一次普通UI保存、一个新进程重开，覆盖全部当前资产和所选Native工况；源再导出一次。不为每次外观修正启动完整Native收尾。
5. **接收一次**：原`accept-paper.py <批号> --validate-only`检查后正式接收，再更新原图册/本包摘要。一份批结论引用真实回执；未完成不计数。规则更新本身不增加支持数量。

### 同族等待复用的精确范围

|检查层|每台保留|可由本批代表机覆盖|
|---|---|---|

## 从搭建到交付

1. 明确本轮用户任务、完成标准和现成资产；沿用已有架构、接口、依赖与授权。新项目先做一个可运行纵向业务闭环；已有项目直接定位当前缺口，不重做脚手架或阶段准入。
2. 只补实现者必须知道的输入输出、状态归属、单位、异常结果和消费者；无需求不增加接口层、配置、日志或未来扩展点。依赖安装、端口和共享写入仅在实际需要时检查。
3. 从原包选一个能闭环的动作：原输入/预期→实现或修复→必要验证→实际消费者。独立预期来自契约，不按结果改答案。实施前置取实际产物，正式关闭仍取原完整出口。
4. 消费有效证据，完成当前包的剩余适用出口；发现阻塞生产者由统筹处理。获准并行时仅派给空闲窗口、固定独立输入/写范围、无必须通信的完整任务，执行中不打断；共享Native只由一个操作者持有。
5. 固定交付候选后按当前授权出口完成尚缺验收及材料检查；仍适用的并发/持久化边界保留，v1已取消的压力矩阵、第二机、指定客户端授权及逐素材权利确认不恢复。人工签认、公开访问和发布如实分开记录。

## 底层执行入口

`tools/dev/verify.mjs`包装已有Node、typecheck、Cargo入口，默认只列命令；`--run`才执行。它不安装依赖、不启动Native、不生成新候选、不重写验收预期或任务状态。任务自身有专用Host/场景入口时优先使用它，不必再套一层。

```powershell
# 文档：只读取明确文件并解析JSON
node tools/dev/verify.mjs --kind docs --file docs/04_开发与验收/剩余任务Todo.json --run
# 单个既有Node行为测试；路径由当前缺口确定
node tools/dev/verify.mjs --kind node --test tools/dev/verify.test.mjs --run
# 前端：先类型检查，再执行显式给定的行为测试（如有）
node tools/dev/verify.mjs --kind frontend --test tests/planner/workspace-refresh/refresh-order.test.mjs
# Rust：显式包与筛选，不默认全workspace；去掉filter才运行该包全部测试
node tools/dev/verify.mjs --kind rust --package sf-domain --filter TEST_NAME
```

后两例是查看执行计划，实际测试时将路径/筛选替换为当前任务的有效入口再加`--run`。已有全量`npm run test:rust`和`tools/s07/verify.ps1`保留，分别用于明确需要的全量回归/工程准入，不作每次续接默认动作。

运行失败就处理实际失败，复验受影响部分；通过后停止加码。缺测试可用直接行为观察验证，不能为了满足“有测试”写只检查实现字符串、标题或行数的测试。工具退出码必须保留，未运行不写通过。

- 技能、全局配置、记忆及产品源码各自保留边界；本次更新不写记忆，不自动提交或推送全局技能。外部动作沿用明确授权，缺授权时先准备可审阅成果。

## 技能分工

`superfactory-dev-entry`按需导航；`task-package`限定当前包/动作；`review`审真实增量；`delivery`做消费者/候选/材料出口；`software-engineering-master`只处理跨层判断或工作流问题。明确的普通小改直接做，不串行加载全部技能。当前使用项目自有Playwright/WebView2驱动真实Native，复用Host、实际文件/进程和浏览器/播放器；[无ComputerUse验收方案](无ComputerUse验收方案.md)中的方法仅在当前出口适用时消费，不恢复已取消的正式矩阵。
