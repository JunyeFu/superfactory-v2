# P0-01 原步骤2/4：关闭并发缺陷与收口

本轮按[逐包收口计划](逐包收口计划.md)接续P0-01，不启动下一包或恢复Playwright。范围为主窗口关闭保护、同一Host的修订/任务接收与原NFR-08并发边界。

## 复现与缺陷

原`useWindowClose`先读取`project_close_state`，随后直接在前端调用`desktop.destroy()`。对干净工程，这两步之间若接受新的工程编辑或导入任务，旧快照仍可导致窗口退出。原六项处理逻辑回归中两项失败：外部新修订、快照后的导入；其余正常关闭/取消/确认及确认期间改版四项通过。

证据：[原始失败](../../.work/single-window-20261019/p001-closeout/close-race-red.log)。此复现运行真实TypeScript处理逻辑、隔离原生依赖，不是普通Native或完整NFR验收。

## 实现

- 前端保留未提交输入、活动任务与关闭确认处理；最终调用私有`project_finish_close`，提交所确认的完整快照及`discardConfirmed`，不再自行销毁窗口。
- 原生边界只接受实际`main`窗口身份，与UI/外部Agent共用同一Host锁。在锁内核对工程/修订、定义草稿、dirty和活动任务，调用实际窗口销毁。
- Host接受关闭后拒绝后续公开请求，防止等待该锁的编辑在窗口退出后提交；若原生销毁失败则解除关闭状态，原工程仍可编辑。活动任务或未获确认的未保存内容仍拒绝关闭。
- 此为既有生命周期的私有适配，不新增公开业务操作、库存、时钟或公共错误码，不改变文件格式。
