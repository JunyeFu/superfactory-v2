## 有限走查案例

- **E01 折叠不吞等待、不累加并行周期**：组含两台设备，同一 [0,10000) 一台有效加工、另一台有实际等待。 预期：组行同时显示加工 1/2、等待 1/2；展开后各自原区间；不能显示整组全忙或周期 20000ms。
- **E02 共享人员与阶段等待**：沿既有 CNC 例：上料 10s 要人、自动 45s 释放人、下料 5s 再要人；下料人员不可用。 预期：设备占用保留；自动段 10—55s 与等待/下料真实区间分开；不开新完成数、不用名义 60s 补完实际。
- **E03 吸附仅对齐输入**：拖一个释放标记吸附到选中参考事件 120000ms；材料到 125000ms。 预期：输入释放=120000ms；实际开工由重跑确定且不能仅因吸附显示 120000ms 开工。
- **E04 编辑联动不修改实际 Run**：显式选择同方案两个到料标记 10000/20000ms 联动 +5000ms，交期和班次未选。 预期：提交新输入的到料为 15000/25000ms；交期、班次不动；旧 Run 区间不变，新 Run 重新计算。
- **E05 末态、部分计算与历史身份**：Run 观察窗到 600000ms，但只计算到 300000ms；工程草稿随后移走设备；选中旧 Run 的 100000ms。 预期：300000ms 后灰罩未计算；100000ms 用旧 Run 冻结身份和 ObjectsAt；不把 final_items 当该时点库存，不用新工程重解释旧作业。
- **E06 待料统计与手动组优先**：设备D1有Engine待料记录，D2加工；将D1手动移为独立行后按所选范围重置自动归类。 预期：组内等待不能因未齐套而漏计；D1在当前视图唯一出现，重置不会修改实体流水线或派工。
- **E07 同刻闭包与零时长事件**：同刻到料、移交、阶段完成、新作业开工，包含零时长阶段。 预期：共用同刻标记，列表按sequence；下一事件时刻执行完整闭包；不伪造毫秒间隔。
- **E08 复用模块与阶段中断证据**：两个设备复用同一工艺模块；一个阶段离班中断后恢复，Run在恢复过程中只形成部分结果。 预期：TC01绑定唯一设备；TC02仅画有效工作段并把computed_boundary端标为未完成；占用不能替代加工。真实执行数据未提供时保持未知。

这些案例actual_result均为null；TC01/TC02类型与有限契约证据已具备；实际阶段/设备绘制仍需真实Engine/Host结果。

## 主轴/子轴现行完整定义

本轮用户已明确采用推荐：共享时钟不变，在同一底部面板按组/设备展开、按绝对选段细化；设备阶段/资源/等待为只读运行明细，图片姿态为独立表现编辑。窄时间轴与只读描述区分别由窗口菜单控制，下方工具带保持。完整字段、动作、状态、异常、保存和有限预期见[完整定义](时间轴主轴与子轴完整定义.md)及[JSON](时间轴主轴与子轴完整定义.json)。


本批DRF01纠偏：dock显隐统一取“窗口”菜单，“视图”负责相机/LOD/时间缩放。选中事件只更新共享选择，不自动打开已隐藏描述区；显式重开恢复尺寸/局部轴窗/滚动/事件，返回保留主动选时。对应DTC07—09和[完整分工定义](../04_开发与验收/特征细化/DRF01_完整定义.md)。
