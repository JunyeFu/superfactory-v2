## 用户拿什么开始，怎样完成

|工作|用户决定|系统处理与可见结果|下一步采用什么|
|---|---|---|---|
|新建草稿|设备用途；仅外观或完整设备|名称、分类、当前缺项；允许先保存外观|同一可继续编辑草稿|
|定义作业|已有行为、输入输出、配比、资源、阶段与工时依据|先显示“需要什么→处理什么→得到什么”；未知能力标未支持|作业定义，不从照片猜工艺|
|选择表现|静态图、图片序列、GIF、模型或原生部件|导入素材，选择单位/朝向/原点与设备占地；资产原点与厂房放置位置分开|表现和端口锚点|
|编辑过程|按周期比例或绑定实际阶段；数据和操作标签|阶段、资源占用与画面分别显示；等人时姿态保持，数量读实际端口|过程表现映射|
|隔离试用|选择示例来料、资源、输出接收条件|外观预览与行为结果分栏；引擎未实现时“未执行”|明确支持范围和待补条件|
|存入本地库|版本、说明、素材来源；可只存私人草稿|外观草稿、完整设计包、实际已验证包分开显示；保存不等于发布|可重开设备定义|
|加入工程|实例名称/位置、物品映射、参数覆盖、真实资源与库位|定义不含正式库存；实例连接到已有工程对象|指定版本的产线实例|
|修改并采用|改实例参数，或改库中定义并选择升级对象|列变化、受影响端口/标签/作业；用户采用后进入设计方案|明确的新方案，旧方案继续可查看|
|交付/贡献|哪些文件允许带出，谁接手维护|同一包、示例、支持范围、缺项和许可；提交仍由贡献者操作|可编辑资产，不只是一张效果图|

默认先选行为再配素材，已有图片可先存外观草稿。纯外观可以出现在布局讨论中，不能被计成有产能的设备。缺价格不阻止时间彩排；缺当前工序必须的行为/资源/连接则阻止它开工。使用者可以用明确的内置示意图替代缺失表现，而不是因缺照片丢掉工序。

## 定义、实例、方案和结果

资源定义中的容量、角色和资格是新建实例的初始值；新实例仍须选择实际日历。升级已有资源只更新所选实例的精确 `definition_ref`，保留其实例容量、角色、资格、日历、地点和表现。若要采用新默认值，进入“人员与共享资源”明确修改对应实例并检查、确认应用，再重新运行；仅升级版本不能宣称运行已使用新容量。旧 Run 继续读取自己的冻结资源和日历。

设备定义保存模块id/version、端口、行为、参数、表现和示例；厂房实例保存自己的id、所用定义版本、位置、参数覆盖及连接。工程库存、人员和订单属于工程，不复制到模块库。两台相同设备不是一台设备的两个外观。

实例参数只能覆盖定义中公开的参数。物品类型参数按现有item_parameter解析；没有此参数的端口不能因名称近似自动改型。资源角色需要绑定工程里实际存在的人员/资源；未绑定时是缺项，不能自动造一个工人。行为端口和画面端口锚点都用稳定端口ID，但锚点不定义接收容量。

任务定义的实际消费者是工艺路线：`RouteStep.operation_ref`引用精确的准备任务版本，并明确执行设备及资源角色绑定；“生产任务与分配”的`Scenario.production_tasks`负责排产输入，不能代替准备任务定义。任务创作的“进入本类实际消费者”进入工艺路线分区，仍须明确选择路线和步骤；保存或提交库版本不自动修改既有路线。未采用的精确版本先核对采用，取消保留原绑定。准备任务改变就绪状态，制造产出仍由工艺规则负责。

工艺规则采用到设备时，保存明确选择的`operation_binding`和角色映射；映射逐项合入`role_bindings`，保留未涉及的设备容量、端口、库位和其他角色。采用不自动改写既有路线：进入本类实际消费者应打开工艺路线分区，由用户核对步骤的精确`operation_ref`、设备和物品/资源绑定。只更新设备默认工艺后，旧路线与它不一致仍作为待修正草稿显示，不自动运行或将旧Run换成新输入。

设备阶段与参数页应区分模块声明与实例覆盖。切换独立工艺后，原内联工艺专用参数标为失活并停止编辑；已有覆盖须由用户点击“移除此实例覆盖”、检查变更并确认应用，不能静默搬到新工艺。移除仅恢复当前所选精确工艺声明，同时清除该参数配对的来源，保留其他参数、映射及旧Run，支持草稿撤销与重做。工作台的运行拒绝须可展开全部实际字段原因和相关对象；定位入口在无未提交编辑时打开对应草稿消费者，不能用错误定位丢弃表单。

修改当前实例不改库中定义或其他实例。“另存为模块版本”才产生新定义；旧方案仍指向旧版本，不自动升级。版本号标识作者发布的内容，不证明兼容性。采用新版本前比较实际变化：

|变化|处理|旧结果怎样使用|
|---|---|---|
|只改插图、镜头或标签位置|行为、布局包络、工时、端口均保持；选择新表现用于新草稿|仍是旧方案结果。可以按同一状态展示新外观，但不新增一次运行成功记录|
|改工时、资源、配比或条件|生成行为变更，使用共同初始条件重新彩排|保留旧结果，不把旧产量挂到新输入|
|改设备占地、路径端点或布置|检查受影响布局；路径模式重新计算，固定时间仍注明来源|旧布局的运输结果不能直接称为新布局结果|
|新增/删除/改型端口|逐条列受影响连接、标签和示例；人工重接|保留未采用草稿与原实例，不自动按名称接线|
|只重命名端口显示文字|ID与类型不变；连接和标签仍用原ID|不是业务连接变化|

升级前可取消，取消保留原实例。运行中点“修改”打开下一方案草稿，当前执行继续使用已开始的方案；预览与草稿修改不直接改当前在制物品或资源占用。无需新增在线版本服务或模块市场。

## 时间轴：总时长不总能按比例缩放

现有单阶段固定工时样例仍采用全周期归一化进度u∈[0,1]，片段和装饰性阶段名称随这个工时显示；插图排序不改变行为。新增多阶段设备按实际phase_id和该阶段有效进度绑定表现，不用全周期播放位置猜当前资源。

阶段内可以排序图片。已经绑定具体生产阶段的片段跨阶段拖动时，要显式选择新阶段；重新绑定表现仍不改变工序顺序。要改变作业阶段或资源，进入行为编辑并作为方案变更说明。不能在“下料”画面里偷偷提前释放机床。

多阶段总时长是各已知阶段工时之和。固定或人工确认阶段不会因修改一个“总周期”统一压缩；允许按比例缩放的阶段需由行为明示，修改后先列各阶段新值再采用。等待/人工确认未知时不显示一个虚构的整体剩余秒数；可以显示当前有效进度、等待时长及下一已声明事件。

### 同样叫等待，实际有四种画面

|业务情形|姿态/画面|物品与资源|时间标签|
|---|---|---|---|
|未开工，缺料/无人|开工前空闲姿态|来料仍在各库位，没有当前在制|无当前周期；显示等待条件|
|阶段边界等下一资源|保持上一已完成阶段终姿态|保持设备/在制；已结束阶段资源按规则释放|有效进度停住，下一阶段未开始|
|有效加工途中服务中断|保持中断时姿态|按工艺pause_resume或abort处置，不能统一假定可恢复|进度停住；暂停等待与有效加工分开|
|加工结束，输出接收满|完成姿态及“待移交”|结果仍在设备，按hold_on_output_wait保留设备；不同时出现在输出库位|有效加工完成，移交尚未完成|

idle/waiting的通用素材只适用于它声明的范围；阶段等待优先采用持有姿态，不无条件回到open。观看循环、回看和LOD不改变上述规则。状态来源、未绑定读数与预设检查结果明确显示。

自建CNC例：上料10秒、自动45秒、下料5秒；下料员55—70秒不可用，则有效加工仍60秒、生产作业75秒才做完；若输出到85秒才有空位，设备85秒才释放。在60秒回看时仍是加工后等待下料，不是空机，也不能靠动画结束生成交付量。

## 标签与操作的具体对象

port.available读取选中实例所绑定库位的可用量，并同时显示物品、单位与位置；它不是整厂同名物品合计。active_item读取当前工序物品，空闲时显示“无当前物品”，不保留上一件检验读数。模块示例用例中的库存不作为实例正式库存。

device.completed_output显示指定端口的“工序做完量”，device.accepted_output显示“已移交量”；二者都是读数，不再次生成库存。上述CNC例80秒是做完1、移交0，85秒才是1/1。质量放行、包装与订单接受还各有条件，不能把这两个计数冒充客户交付。

删除端口、参数或原生部件时，编辑器列出依赖它的标签、连接与锚点；用户选择改绑、删除标签或保留待补。保存草稿允许缺项；用于运行的工序需要其真实条件完整。仅说明标签未定位不阻止行为执行，但缺失的专业结果源不能用文字替代。

configure编辑草稿参数；inspect查看当前对象与端口；preview_cycle只执行隔离示例。正式运行的开始/暂停/单步/复位仍在整厂工具栏。“夹紧、点动、确认”等热点没有对应行为时显示未支持；操作出现在哪张图上不增加能力。Agent调用同一命令，也不越过这个范围。

## 本地导入和交付边界

工艺投入配比的 `required_quality` 是允许领用的质量状态列表；空列表不会允许所有质量，实际作业会等待质量条件。需要未检验或已放行物料时，分别明确添加 `unchecked`、`released`。`QualityState.released` 显示为“已放行”，定义状态 `DefinitionState.released` 仍显示“已发布版本”，两种状态不混用。质量条件修改遵循定义草稿、隔离样例、提交新精确版本、实例明确采用和路线显式引用的现有流程；旧版本及旧 Run 保留。

贡献导出使用实际 ZIP 保存文件选择器，选择文件名后导出已提交的精确版本，不自动发布。类别包导入先读取实际 ZIP 并显示精确版本、素材许可、缺项与冲突；确认导入定义之后，实例采用与角色映射仍是独立明确操作。当前工程导入必须保持原工程身份和业务输入，源包库存、运行结果和认可不能随定义进入工程。

独立模块贡献包的缺项范围随所选精确定义、递归依赖及显式专业成果收敛；不带入当前工程其他对象或未选素材的缺项。所选依赖真正缺失的素材及原许可仍须保留，不能通过缩小导出范围掩盖。新创作的本地设备组合可声明仅覆盖自身端口和组合内容的测试来源与许可，不能替依赖规则、原素材或旧不可变版本补造作者与再分发权利。

素材和包是外部输入，导入共同检查包内路径、支持格式、资源引用、类型/单位、能力名和实际引用关系；上传数据不运行任意脚本。模型尺度用于表现/布局，行为耗时仍有独立来源。素材损坏或不支持时保留草稿，列具体缺项；明确选择内置图标后可继续正确业务，不静默冒充原模型。

私人可使用的照片不等于可再分发。导出分三种：私人本地工程、可交接设计包、公开贡献包。后两者逐资产决定附带/引用/替换，提供真实来源与缺项；许可未确认不自动附带。已取得授权的文件才能随包公开，原始行业报告不因用于研究就加入设备包。许可文本采用实际文件声明，不预先替贡献者选许可证。

贡献者可以只改外观或标签，也可改行为；前者用同一行为示例说明读数/动作对应，后者提供新的明确输入和预期。维护者能重开、修改和运行之后才列为实际已验证版本；现在的案例全部是设计。具体贯通预期见[设备创作与采用](../../scenarios/设备创作与采用/README.md)，拟议能力继续在现有module-kit清单维护。

## 持久化物品展示槽

设备/库位/容器的空间展示由`DeviceInstance.item_layout`、`StockLocation.item_layout`、`ItemType.contents_layout`明确创作。正常入口为“编辑→物品展示槽”；选择实际owner、精确子类型@revision、`item_id_order`、完整offset的单位/坐标/平移/四元数/尺度。设备和容器选择最终精确媒体的命名scene_node角色，库位anchor为null并相对实际Location。角色可分别核对详细/简化LOD；不把图像锚点或工艺角色充当3D节点。

未声明与显式空槽分开保存；没有自动槽位或Pose。应用沿原PutObject、ProjectR、Undo/Redo和保存，取消/修订冲突保留本地输入，新Run冻结新声明，旧Run仍读旧布局。展示槽不改变业务capacity；同一holder及精确类型的实际身份按ID字典序配声明槽顺序，超槽整组明确缺项，不按数量复制物品或猜运输位置。唯一字段、引用/授权与模板规则取[共同类型规范](../03_架构与契约/全层类型与工程格式.json#/typed_item_slot_layout_contract)。

当前生产者9项真实Host/3项模板已接收；普通工作台入口与场景消费者已冻源接收，主12组及实际75/80等待→85移交→反向75的1组通过，同一物品身份、原库存/时间/事件保持。独立及完整Planner TS/web构建通过；这不是Native、工业资产认可或原完整release通过。


## 运输定义与实际供应的明确接续

运输定义的导入、采用和供应引用是三个独立动作：导入仅入本地库；AdoptModule无目标时只明确纳入Project.module_refs，不制造载具、库位、物料或供应；进入“供应与运输输入”另行检查并确认所选Scenario的SupplyRelation.transport_ref。其他方案仍使用自己的精确版本。运输草稿样例必须选已映射同一来源id/version且scope=[]的实际方案；样例使用冻结Draft，不改正式Run。普通Native48—49已验证0.1.1去程20秒、原载具T1和原库位、单独修改SUPPLY与新进程读回；旧Run继续使用旧冻结版本。


## 专业定义与实际消费者的精确边界

专业定义导入只进入本地库；进入当前工程的精确专业消费者之前须明确采用该版本。纸包装桌面仅消费professional类别且output_artifact_type为paper_packaging的定义，包含库入口与DefinitionDraft菜单；其他计划提供者保留声明、保存和贡献入口，并明确提示尚无实际执行消费者。纸包装计算继续使用已有compute_packaging操作和显式专业输入，不执行贡献包任意提供者。计划数控定义不能因同属专业类别而进入纸包装消费者。


## 纸包装原草稿、定义贡献与独立专业成果

纸包装原草稿保存专业输入后，compute_packaging在该DefinitionDraft中生成独立Artifact。专业输入和不可变版本形成草稿历史边界，之后普通定义编辑仍可撤销/重做，不能回滚既有成果或磁盘导出。定义贡献包只携带精确定义；导入及明确采用不得复制源草稿成果、工程库存、认可或绑定。真实专业成果另行导出专业工程包；打开保存Artifact读取其原冻结输入和结果，当前本地输入不同须明确提示，不重算覆盖。制造文件缺少本次携带许可时列为缺项，不能用计算通过替代许可或人类用途认可。


## 表现内部锚点与业务采用边界

Presentation.anchor_roles保存表现内部的图像归一化坐标、场景部件索引或视口坐标，不是业务ObjectRef，也不在采用页要求对象映射。真实target_role、物品、资源与port_anchors仍按各自命名空间明确映射。采用表现只为明确选择的设备设置精确媒体引用及presentation_override，不替换设备模块、工艺、角色绑定、姿态或生产输入。定义内的部件、命名姿态、单位、坐标系和根缩放随精确版本保存；旧Run继续读原冻结输入。定义许可缺失时阻止贡献导出，不能用本地提交、预览成功或测试声明补造原素材的作者、许可或再分发确认。


## 创作预览的实际素材来源

共同画布预览使用当前表单的 Presentation，并单独携带已实际读取的精确库版本或 DefinitionDraft 标识与修订。素材通过同一 Host 的实际授权字节入口和共同媒体渲染器读取；静态图、图片序列、GIF、GLB、原生部件及纹理按既有支持能力处理。未保存的新定义没有 Host 来源，只提供原生部件核对；修改已读定义的标识、版本或新增素材引用，不会冒充已保存来源，新引用须保存后由 Host 核对。缺字节、未支持格式、修订冲突和授权失败明确显示，不猜文件路径或改用当前 Run 素材。

创作素材检查是静态呈现，不能制造阶段进度、库存、产量、人员占用或新的生产时钟。当前工程的旧 Run、输入及认可保持；本地能读取素材不等于获得再分发许可。权利字段保留原值，贡献导出继续逐资产决定是否附带。具体实现验证状态见本窗口 P3-01 执行记录；有限检查不代填实际 Native 或整包验收。


## 固定设备的独立规则映射

固定设备选择独立工艺规则时，采用表单按已加载的精确 id/version 同时列出该规则的物品、整段资源、阶段资源及对象角色，再与设备端口和系统 execution_capacity 一起明确映射。只读取已选规则，不用同名最新版本替代，也不推测真实物品或人员。内联规则仍只取本身所选行为。库中提交与实例采用分别确认；取消采用保留原实例，Host 原子检查和旧 Run 冻结边界不变。实施与实际验证状态见 P3-01 当前执行记录。


## 采用后的精确端口与人工重接

采用页按明确选择的实例列出端点仍指其他精确模块版本的连接，包括连接 ID、源或目的、稳定实例 ID、端口 ID 和原 id/version；采用不自动接线。端口选项同时显示设备标题、稳定实例 ID、端口 ID 与精确模块版本，避免同名复制设备混淆。物料连接编辑器保留并警示失效的旧端点，由用户明确重新选择后应用；物品、接收库位及未涉及的原声明保持。

样例在执行准入被拒且尚未生成 Task 时，创作页显示 Host 的实际错误码、对象、全部字段路径和原因；保留 DefinitionDraft 与输入，不生成完成结果。仅修正已确认的连接后可在同一 Draft 对当前明确选定的方案重跑，旧 Run 保持原冻结输入。具体 Native 验证结果仍以 P3-01 执行记录为准。
