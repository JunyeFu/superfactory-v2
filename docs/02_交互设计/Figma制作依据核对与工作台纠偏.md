# Figma制作依据核对与工作台纠偏

2026-10-14。结论：现有Figma生成偏离工业工作台基线，需要重新设计工程外壳和业务工作区。**本轮不修改Figma；修正的是制作依据及其真实文档消费者。S04-02/04/05仍未通过。**

## 额度核查

账户查询实际显示Professional / Collab。只读文件metadata仍返回Collab席位MCP额度耗尽，额度没有恢复。账户查询不受读额度限制，因此whoami成功不代表文件额度可用。[Figma官方额度规则](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/)要求区分套餐与席位：View/Collab仍按月限额，提高限额需要Dev/Full席位。本轮未更改席位、购买或重新授权。

## 依据与实际偏差

最高依据为当前用户明确的“工业软件风格、中央大画布、左右伸缩、上下固定栏”。既有Q06已选A明确中部3D、右属性、可收起库和底部时间轴；[主流程](主流程与视图导航.md)规定同工程外壳与面板。[原始视觉设计](../../../设计预览/多层视图与对象设计.md)和[母版提示词](../../../模块研究/从零搭建案例图包/整体母版提示词.md)明确浅色工业桌面工作台，母版禁止宣传页/指标仪表盘。旧图的英文或过期四标签不沿用，现行中文和两画布语义优先。

|严重性|发现|证据与影响|
|---|---|---|
|P1|生成器丢失布局输入|build.py:17仅提取帧身份/标题/表单/导航，未向screens.js传递视觉基线或外壳布局。|
|P1|中央变成说明页|screens.js:44让18/24主帧使用大说明卡片；多厂房/纸包装/比较/报告缺对应工作区。|
|P1|左右伸缩缺失|screens.js:31/33固定224px/416px，仅纵向滚动，没有收起、分隔柄、宽度状态和中央填充。|
|P1|顶底栏语义丢失|screens.js:29/30用品牌栏和案例条代替紧凑工程菜单工具，底部只按坐标绘制时间条。静态位置仍在，但固定行为未落实。|
|P1|网页控件密度|foundation.js:17/19采用200×44按钮和352×112属性卡片，偏离旧L03的紧凑命令、属性行和任务表。|
|P2|检查范围不足|原准备检查只核引用/数量/流程；不检查风格、伸缩或固定栏，不证明原型符合要求。|

上述结论核对本地生成源、上轮真实VP05截图和旧L03参考；当前Figma重新读取受限，不声称覆盖后来人工改动。配额问题与设计偏差是两项独立事实。

## 已补回的统一工作台要求

- 顶部工程菜单/两画布/命令工具与工程归属、底部时间轴/任务表/状态区固定在工程外壳。
- 左侧对象树和模块库、右侧对象属性可收起/恢复、调整宽度；滚动不能代替伸缩。
- 中央填满上下栏及左右面板之间的剩余空间。正常任务保留3D画布；专业/比较/报告使用相应业务工作区，说明进入帮助或紧凑侧栏。
- 收起、拖宽、滚动和返回保留工程/草稿/相机/选择/观察时点；不换画布、不增常态工作空间、不拥有库存。
- 恢复紧凑工业命令、树、属性行/分组和数据表。具体字号/行高/宽度留给单帧监督核对，不把现有网页卡片尺寸当已认可基线。

完整机器规则见[JSON](Figma制作依据核对与工作台纠偏.json#/layout_contract)。现有生成器不得直接继续扩批；resume-layout.js只修裁切，不能解决此次整体偏差。用户本轮暂停Figma制作，额度恢复不自动恢复操作。
