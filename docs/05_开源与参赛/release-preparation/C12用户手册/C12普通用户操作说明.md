# 超级工厂 C12 普通用户操作说明

适用：软件 0.1.0 / C12，设备样例 `p201.b60.station@1.0.5`。作者：傅钧烨。2026-10-23。

本手册带你打开已有工程、阅读历史实际 Run、检查等待和物品去向，再保存、关闭并搬移重开。**回看已有结果不需要点击“运行方案”。**

## 1. 准备软件和工程

1. 在 Windows 11 x64 上完整解压目录包到可写位置，保留 `superfactory.exe`、`modules/`、`report-resources/`、`demos/` 和 `NATIVE_DELIVERY.json` 的相对位置。从该目录启动 `superfactory.exe`，不要只复制 exe。需要可用的 WebView2 Runtime；若系统实际报缺运行库，按错误补齐。普通使用不需要安装 Rust/Node 开发环境。
2. 先把要使用的演示工程**整个目录**复制到自己的工作位置。随冻结目录包提供的是以下两例；本手册附图使用的日历案例不是这两例之一。

|工程|在包内的位置|应选择的历史 Run|
|---|---|---|
|缺料演示|`demos/missing-material/`|`B60-105-missing-material-50268:run:1:2`|
|高密度演示|`demos/dense/`|`B60-105-dense-47464:run:1:2`|
|日历验收工程，另行取得时使用|提供者交付的完整日历工程目录，不假定在 demos 中|`B60-105-calendar-nonpreemptive-46836:run:1:2`|

没有日历工程时，用缺料演示练习打开、选择 Run、保存与重开；第 4 节日历时点只作为配图阅读，不能套用为缺料或高密度工程的预期结果。此手册不附工程数据。

## 2. 打开并明确选择历史结果

1. 点击 **文件 → 打开工程目录…**，选择包含 `project.json` 的**目录**。ZIP 工程用另一个入口“打开工程ZIP…”。不要在目录选择器中寻找单个 JSON 文件。
2. 在“打开工程 · 采纳前核对”中查看缺项、冲突和精确模块版本，再点“确认打开”。若当前已有工程，先确认没有需要保留的未保存修改或定义草稿，再在“离开当前工程”中选择“工程已保存、定义已提交，继续”；有需要保留的内容则返回原工程保存或提交后再打开。若有缺项，不要把“保留缺项，以可编辑草稿打开”理解为已经能完整运行；复现本手册需要提供者给出完整对应工程。
3. 在中央画布上方的历史结果下拉框（初始显示 **未选择 Run**）选择表中对应的完整 Run ID。检查界面进入 **实际回看**，左侧显示 **Run 冻结输入**，顶部列出冻结修订和冻结方案。
4. 右侧比较框可保持 **不选择比较 Run**。当前草稿方案的选择不代替历史 Run 选择；回看应以 Run 所属的冻结方案为准。

若看不到时间轴或事件描述，在 **窗口** 菜单显示“时间轴”“事件描述”；也可用“恢复默认布局”。中央是画布，左右为对象树和属性区；上方工具区与下方时间轴是固定分区。

## 3. 在时间轴与设备过程里看同一件物品

1. 底部“全厂主轴”选择 **实际**，展开厂房/流水线，找到设备行，例如 `L1-D01`。点击具体阶段或等待条，让“事件描述”显示对应 Run、作业、等待条件和阻断对象。
2. 在时间轴底部数值框输入观察时点，单位 **毫秒**，点 **读取时点**。例如 `1500` 是 1.5 秒，`4000` 是 4 秒。用“播放回看”连续观察，用“暂停回看”停下核对；精确比较优先输入时点。
3. 若“事件描述”里出现 **查看所选作业过程**，点击它，保持所选作业身份。也可在对象树选设备，再点 **设备过程 → 所选设备的过程…**，或属性区的“查看设备过程 / 图片编辑”；进入后仍需确认来源是**实际 Run**，而非“声明预览”。
4. 设备过程顶部有 **实际观看时点** 和 **重读实际来源**。修改数值后用“重读实际来源”读取，核对“观看 … ms”和 Run ID，避免把尚未读取的输入值当结果。
5. 看“阶段与持有”的实际阶段、画面进度、等待、实际持有，再看“物品身份”和右侧“实际物品记录”。用同一个物品 ID 跟踪它的 holder：它可能在源位置、当前作业或下一作业。设备画面不显示某件物品时，先查其持有者，不以模型消失推断丢失或报废。
6. 点击“返回工作台”离开设备过程。回到时间轴时继续核对同一个 Run、时点与作业。

## 5. 读懂等待与时间

|现象|怎样解释|
|---|---|
|缺料|等待所需物料。缺料演示的历史记录在到料前没有该物品；不要用日历案例中“物品在源位置”的状态替代。|
|资源排队|所选作业等待资源；设备忙可能属于别的作业，须核对作业 ID 和占用者。|
|日历条件未满足 / calendar|可能是日历关闭，也可能是当前开放窗口剩余的连续时间不足。此设备周期不可抢占；不能一概解释为“日历关闭”。|
|输出空间不足 / output_capacity|加工进度可以达到 100%，但输出仍受阻，资源和物品可能继续被持有。100% 不等于已交接或已被客户接受。|

[查看 C12 修正后的日历文案](screenshots/C12-calendar-label-fixed.jpg) · [查看 C11 输出受阻历史原图](screenshots/output-2000-blocked-boundary.jpg)

观察时点是你**正在看哪一刻**；“已计算至”是 Run 实际算到的边界。进度和动作姿态用于显示这个时点的状态，实际开始、完成、交接与接受要以事件和物品记录为准。播放速度、倒退回看或切换相机不会重新领料、释放资源或生产新物品；“返回当前”读取已计算边界，不是继续生产。没有记录的后续时点不能推断为已经发生。

## 6. 保存、关闭、搬移与新进程重开

1. 如有未应用的表单输入，先返回对应编辑区，决定应用或丢弃；需要保留的修改应用后再保存。
2. 点击 **文件 → 保存工程…**，在目录选择器中明确选择保存目标。等到出现 **已保存 r…**。如果同时提示“当前仍有新修订未保存”，应再保存当前修改，不能就此搬移。
3. 记下工程目录、完整 Run ID、物品 ID 和观察时点。点击窗口右上角关闭按钮，等待正常退出。有未保存内容时按提示决定保存或返回；本次要保留工程，不选丢弃。操作或任务未结束时，完成或明确取消后再关闭。
4. 软件关闭后，在 Windows 文件资源管理器中搬移**刚保存的整个工程目录**，包含 `project.json` 及其全部子目录、模块和资产；不要只移动清单或结果文件。软件安装目录与工程目录是两回事。
5. 重新启动软件，按第 2 节打开新位置的工程目录，并在历史结果框重新选择原 Run。不要用“运行方案”补出旧结果。
6. 重新读取同一时点，核对精确版本、Run、物品 holder 和资源状态。日历工程的 C12 既有验收中，保存修订为 r6，搬移和重开后 13 个文件一致；1500/4000 ms 状态分别如第 4 节。窗口布局或选择位置不应代替这项内容核对。

![C12：等待“已保存r6”提示后再关闭搬移](screenshots/C12-native-saved-r6.jpg)

## 7. 什么时候才点“运行方案”

只读旧结果时不用运行。若要改变参数并评估新方案，回到“输入草稿”，应用明确的改动，再执行“运行方案”，选择新产生的 Run 阅读结果。旧 Run 仍代表旧冻结输入，不能用它解释新参数。本版不把拖动时间轴当作从该时点继续仿真；新方案计算与历史回看是不同动作。

## 范围说明

已完成证据是 C12 限定日历文案、工程保存搬移与新进程重开后的等待/持有/接触，以及明确标注的 C11 历史案例。本手册本身没有启动软件或重新验收；Root 已另行完成 C12 目录包启动、两份随包原 Run 回看、正常退出及 25 文件保留核对，C12 R3 十页介绍 PDF 与可编辑源已接收，49 秒真实流程视频已在本地完成，公开视频 URL 和包含 C12 的最终仓库 commit 尚未发布，正式上传或提交未办理。完整 MQ/NFR 与人工验收不由这份手册宣告通过。截图出处与版本见[截图清单](截图引用清单.md)，早期录制建议见[历史 MAT-03 镜头清单](MAT-03录制镜头清单_尚未录制.md)；其文件名中的“尚未录制”保留历史命名，不代表当前本地视频状态。


## 源码交接补充

普通用户使用完整 Windows 目录包，不需要按源码构建。需要接手源码时，当前接收的源码打包修正版是 `superfactory-source-C12-cachefix.zip`，必须与 `superfactory-source-C12-cachefix.manifest.json` 一同交付。修正版精确删除 160 项历史 npm/WebView2 缓存并替换制包脚本；其余 29,359 个 ZIP entry 解压字节保持一致，源码与资源闭包通过，Root 已接收。ZIP 内 `SOURCE_DELIVERY.json` 按原字节保留为历史清单；修正版文件列表、字节数、排除项与候选身份以同名外部 manifest 为准。它是 C12 打包修正，不是新的应用版本。原 C12 ZIP 保留，但不能将原 ZIP 描述为无缓存包。

源码声明 Node 24.15.0 / npm 12.0.1；C12 已记录的实际检查环境为 Node 24.19.0 / npm 11.12.1，Rust/Cargo 均为 1.97.0。声明与实测分别保留，冷缓存依赖恢复未验证。 源码不提供完整 npm/Cargo 离线依赖镜像；上述情况不改变普通用户的运行步骤。
