## 1. 运行前准备

|项目|准备内容|
|---|---|
|客户端|使用明确通过验收的 Windows 候选及同包资源；保留原工程、旧 Run 和现有私有配置|
|设备运行时|随包 `v2-devices/` 内的 CPython 3.14.9 与可信脚本；不要用上传脚本或系统 Python 代替设备端|
|云服务|实际 Sealos HTTPS 与 PostgreSQL；部署说明见[Sealos交付说明](../../../../tools/cloud/sealos/README.md)|
|本机连接|部署者提供当前工程的私有 `connection.json`，按 Native 约定放在 `%APPDATA%\org.superfactory.planner\v2-cloud\`|
|示例工程|打开[geometry-v4/project](../../../../resources/v2-demo/geometry-v4/project)，同时消费同目录 `candidate-bindings.json` 和 `profile-bindings.json`|

连接文件的现有字段为 `connection_ref`、`project_id`、`cloud_project_id`、`endpoint`、`reader_token`、`gateway_token`、`candidate_bindings`、`devices`。身份和凭据由实际部署者配置；不要从示例说明拼造令牌，也不要将配置、设备 journal 或数据库连接串放进代码/交付包。Renderer 不保管云凭据。

推荐入口是实际 r4 示例，不是旧根目录 r2。工程为 `Task8-two-device-six-units`，方案为 `Task8-six-units`；保留三个原预测 Run。设备 A/B 的实际工时为10/15秒，输入六件、目标六件，精确设备版本 `p201.b60.station@1.0.6`。不为演示重写旧 Run 或替换冻结素材。

## 2. 正常生产

1. 在普通客户端打开上述 `project/` 目录，确认工程/方案 r4、两台设备及三个原 Run 仍可读。进入原工作台的“云端生产”。
2. 选择“执行”页签。目标数量填 `6`，单位 `piece`，报告截止填 `120000` 毫秒，观测有效期填 `5000` 毫秒；选择 A/B 两条实际绑定。
3. 点击“准备冻结输入”。准备成功只创建会话并冻结本次输入，不自动生产。核对来源、会话及本机控制资格后，显式点击“启动”。
4. 查看“同源接受事件”、生命周期及未决工作。以 Host 的产品接受量和业务状态判断完成，不以指令数、设备自报次数或异步 Task 完成判断产量。
5. 目标满足后等待已准入工作结清，保存工程。原组实测为6/6、Host时间53.202秒；它是软件在环场景结果，不是操作步骤中的固定等待时间。

原始证据见[正常组](../../../../.work/v2-implementation-20261026/sealos-live-deploy/positive-export-verification.json)。不要为了复现相同秒数更改设备工时、缩短截止或改写原输入。

## 3. 停止 A 新接单与改派

1. 保留正常组和其工程保存目录，从原 r4 输入准备一个新会话，显式启动。
2. 在确认 A 的原尝试已经 `Started` 后，于“设备”页签取消 A 的“人工允许”。这里只停止新接单，不要求中断已经开始的命令。已发出而执行结果未知的命令仍查询原命令，不因暂未显示Started就重复派工。
3. 核对 A 的原任务继续完成，之后没有新 A 尝试；未开始工作按实际资格继续分配给 B。
4. 核对六件目标、未决命令、预留和待输出均结清，保存为独立结果。已有对照为 A 1件/B 5件，Host时间97.092秒；来源与正常组分别固定，不能混成同一次运行。

原始证据见[停用对照](../../../../.work/v2-implementation-20261026/sealos-live-deploy/ban-A-verification.json)。若出现来源/修订冲突，保留表单并核对最新 Host 状态；不要据一次界面错误重发生产命令。已有发布背压、能力刷新和前端确认问题的当前状态取主计划，不忽略新错误。

## 4. 读取、完整导出及报告

### 数据页

1. 点击“刷新数据集”，选择实际返回的数据集或“所选执行投影”。生成负载、遥测与执行来源保持各自标识。
2. 遥测/生成数据填写设备ID及 UTC 起点（含）/终点（不含）；执行投影使用 Host 毫秒范围。基准数据的冻结时间范围见其实际输入，不用当前本机时间猜测。
3. 执行查询并固定来源，保留实际 F/设备集合或 R。界面当前页不代表全部选择，目录前沿也不代替查询固定前沿。
4. 点击“导出全部固定筛选”，选择本次真实目录，等待原 Task 完成。检查行数、页数及实际文件；它应包含该固定选择的全部分页，不是只导出当前屏幕行。
5. 需要继续观察同一请求时使用“查询原请求 / 继续观察”。改变筛选则建立新的选择，不把旧 cursor 接到新条件。

工作台先通过110行（超过首屏50行）导出；本轮又完成真实Native UI及独立MCP各10000行/50个后端页的完整导出，每字段与PG独立预期一致。当前候选和固定选择仍按主计划及实际回执取用。

### 同源报告与回看

选择明确的本机执行来源及固定修订，按需选择真实预测 Run，然后“导出同源四格式报告”。等待原 Task 完成，核对 PDF/HTML/CSV/JSON 文件及来源。实际正常/停用报告各22个文件、17张CSV。缺少可比条件的指标保持未知，不把两个时间直接写成物理效率提升。

“云端同R只读”用于核对同一修订的云来源；历史或云只读来源没有本机控制资格。要操作活动会话，应回到具有真实权限的“Host最新R”，不能把只读源提升成可写源。回看只改变观察，不重新领料或生成产出。

保存/新进程重开应保留原工程、旧 Run、实际执行及冻结素材。归档恢复是只读历史，不恢复活动 Engine、旧 Task 或旧控制授权；再生产需明确准备新会话。

## 6. 明确候选的本地交付包

以下命令在“软件工程”根运行。先把尖括号字段替换为真实验收候选及新输出目录，使用已验证的工具 Python（本轮工具环境为3.12.14）。设备端仍使用随包解释器，不依赖这一工具 Python。

```powershell
$sfSource = (Get-Location).Path
$sfCandidate = '<实际验收候选exe的绝对路径>'
$sfCandidateId = '<实际候选ID>'
$sfOutput = 'E:\Deliveries\SuperFactory-v2-<实际候选ID>'
python tools/release-preparation/package_v2.py `
  --source-root $sfSource `
  --candidate-exe $sfCandidate `
  --device-resources "$sfSource\resources\v2-devices" `
  --output $sfOutput `
  --candidate-id $sfCandidateId
```

该工具只组装明确 exe、Tauri 已声明资源、可信设备运行时及现有许可证，不执行构建、升版或实际产品验收。输出必须为新目录；正式交付不传 `--fixture`，该标记只用于复制边界夹具。`V2_PORTABLE.json` 的复制记录不代表新包已经搬移/新进程/云执行验证；这些按最终候选的实际结果填写。不要把 `.work`、缓存、私有连接、journal 或全局环境复制进包。

可运行源码归档使用 `tools/release-preparation/source_delivery.py`，收取实际目录中的新旧源码、示例及资源，不限于 Git 已跟踪清单；保留现有 `resources/v2-devices/python` 可信解释器、DLL和标准库 ZIP。先运行 `python -B -X utf8 tools/release-preparation/source_delivery.py --root . --check` 核对源文件和声明资源闭合；最终候选固定后再用 `--candidate-id`、`--output` 和 `--extract-to` 归档并解压核对。源文件闭合不代替编译或 Native 搬移重开，历史 C17 提交也不代表当前 v2 新增文件已经提交。

Sealos 公共模板可以独立生成：

```powershell
python tools/cloud/sealos/render.py `
  --namespace '<实际工作空间>' `
  --image-digest-ref '<实际repository@sha256:digest>' `
  --public-host '<实际HTTPS主机名>' `
  --https-tls-secret '<实际TLS Secret名称>' `
  --ingress-class '<实际Ingress类别>' `
  --output 'E:\Deliveries\SuperFactory-v2-platform'
```

`render.py` 不连接 Kubernetes，也不创建资源或填写秘密值。真实部署、迁移及私有配置仍按 Sealos 说明和已批准预算执行；不要将模板生成当成部署成功。
