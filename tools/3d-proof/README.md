## L03八设备业务仿真与动作

入口：[本地页面](http://127.0.0.1:19287/) → 流水线 → 运行产线。运行／暂停／单步／倍速控制同一个仿真时钟；单击实例查看同一运行，外观隔离姿态不提交业务。底部显示真实事件，右侧显示库存、占用者与等待原因，可导出本次输入及业务结果JSON。

重置创建新运行、结算0秒的齐套开工事件后暂停，所以此时库存已扣第一套在制用料，ASM01有效进度仍为0%。连续运行在订单全部接受的业务事件处停下，不把浏览器下一帧的时间当作交付时点。

八台设备为ASM01装配、R01搬运、CV01检查前输送、V01检验、RW01返工、CV02装箱前输送、PK01装箱、CASE01封箱。PAL01另为载具资源，不计作第九台生产设备。RW01/PK01复用装配台外观，分别引用返工／装箱定义，不能按相同GLB合并身份。端口/库位支撑架只表现逻辑移交位置，不增加设备或复制库存。

[输入生成源](prepare_line.py)从现有指定版本声明生成[line-config.json](line-config.json)，含八实例、七种局部物品定义、四个不同人员角色定义/实例、托盘、库位容量、订单、供料和质量输入。壳体/成品规格是本例自建定义，不混用另一100mm壳体样例。人员在本例显式覆盖默认日历，连续可用且每种角色容量1；通用班次/换单另待正式产品。原料/工时/质量结果均为声明的演示输入，未冒充工业实测或图像识别。

基线订单6套：0秒有壳体6、PCB2、螺钉24、纸箱6、胶带3.6m；120秒补PCB4。第三套初检失败，返工20秒后复检通过。完整路线是40秒装配→12秒机器人周期（第9秒交付，第12秒回位可再用）→4秒输送→10秒检验→4秒输送→15秒装箱→8秒封箱→PAL01接受。每次装配领用1壳体/1PCB/4螺钉，每次装箱用1纸箱，封箱在阶段完成时扣0.6m胶带一次。装箱建立包含原控制盒ID的新包件；搬运、检验、返工、封箱保持相应原ID。

实际基线接受时点为90、130、240、255、290、330秒，最后接受6/6，四种原料和胶带余量归零，人员全部释放。对应[实际事件与八项业务检查](output/line-business-checks.json)，不是将手算结果填入actual_result。

- 缺PCB情景只交2套；补PCB4后继续同一订单，可完成6套。
- 缺检验结果时V01保留原物品和inspector；补当前检验结果后继续，不默认合格。
- 接收暂停至180秒时封好的包件留在CASE01，胶带不重复扣；恢复接收后继续。
- 第五套初检/复检均失败则隔离原A-005，最多一次返工，最终交5套并显示未交1套。
- 容量检查以13套输入验证PAL01最多接12箱，第13箱保留在封箱机，不能靠画面堆放突破容量。

[局部仿真](line-simulation.mjs)不引用DOM、Three.js或动画时钟；所有完成、移交和开工在同一相对毫秒体系下按稳定顺序推进。[表现消费者](line-view.js)只读取快照，等待和暂停不增加有效作业进度；同一物品在库位、设备、包件及托盘中保持唯一持有关系。不同渲染步长获得相同业务事件。

[设备动作控制](equipment-motion.js)完成：装配台四点XY定位、83mm主轴行程与旋转紧固；机器人六个命名父子关节、固定任务的示意运动学、夹爪、同一货物挂接和随关节/卡箍的线束；输送滚筒/带面标记；检验定位和灯环；人工装箱上料/入箱/送出；同一包件封箱/胶带显隐/出箱；真实0—12箱堆放。机器人夹爪已按统一1:1控制盒宽度适配，装配台加工装垫高并重新绑定四个紧固点；旧固定样例隐藏，沿线采用同源物品外观。GLB保留活动部件，静态合批不抹去关节。

1. 选择设备详情，拖动实际模型并查看背面/底部；“姿态”滑块改变装配台命名主轴或机器人的夹爪部件。

3. 选择详细/简化，点击“测量10秒”：预热1.5秒，然后取10秒样本。保持页面可见。CPU为渲染提交耗时；GPU通过WebGL2计时查询取得；帧回调间隔不是显示器实际刷新率或全产品FPS。
4. “保存模型、画面与测量”输出六类完整GLB、当前1920×1080画面和JSON。模型按二进制逐个发送，避免共享2K材质的六个GLB一次性Base64打包超过80MB；此问题已在本轮实际遇到并修正。
5. “重开导出的GLB”从磁盘读取当前设备，重新合批呈现；原始节点、材质与局部变换均保留。
6. “录制设备动作视频”从磁盘加载装配台与机器人GLB，依次呈现主轴往复的整体/近景、夹爪开合的整体/近景，各6秒，输出[24秒MP4](output/device-motion.mp4)与[参数记录](output/device-motion.json)。按动作预览时间逐帧渲染720帧，再由本机FFmpeg编码为1920×1080、H.264、30fps；30fps是视频输出参数。视频已标注尚未接业务仿真，机器人机身保持现有姿态。
