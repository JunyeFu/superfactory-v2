# v2 production execution consumer

Use the actual connected MCP tools and current principal grants. This repository workflow is not a credential, Gateway, provider installer, new runtime or global client configuration. The actual Rust wire is `sf.execution/2.0-draft11`; API envelope version remains `0.1`.

1. Read `get_context` and current tools/catalog. Preserve actual `Response.context.host_instance_id`, caller `session_id`, `project_id` and revision separately from the execution `identity` (session, epoch, project, Host context). Only advertise/submit tools the actual authorized catalog permits. Absent Native/preparation/cloud providers are unavailable; never use a prediction Run as production. Ordinary Agent cannot call `apply_device_receipt`, `apply_device_observation`, `get_execution_cloud_work` or `acknowledge_execution_cloud_work`, copy device tokens, run arbitrary scripts or call arbitrary URLs.
2. Read the selected current Project/Scenario and H08 `configuration` at its actual base/scenario revisions. Show actual issues and candidate bindings. `dataset_catalog` is discovery, not a fixed data frontier. Prepare only after explicit user authorization with those exact revisions/bindings and the actual policy/cutoff/target/window; do not invent defaults. H01 returns an `execution_preparation` Task. Read its exact ID with `get_task`, verify original operation/request/kind/scope/input revision and actual result `execution_session`. Success means **prepared**, not running. Never call run automatically.
3. Preserve original full request and Task on unknown transport/registration. H09 `request` uses the original `originating_request_id`. A registered result must match actual Host, original operation/request and handle. `not_found` remains unknown; never resubmit H01/H03/H10/H11 to recover a lost response. A new connection needs actual desktop authorization; it gains neither old directory tokens nor old Task authority. H03 has no request-registry result in the current Host contract: keep an unknown control unresolved rather than infer success from a later snapshot.

   The current Host request registry is scoped to the actual original caller. A newly authorized connection cannot assume H09 exposes an old caller's request. If the original Task ID was known, explicit Native access to that exact Task permits `advance`; if its ID was never received and H09 returns not_found, retain the unresolved request. Do not guess the Task or replace it with another preparation/export.
4. Read H02 with exact identity and desired `revision`, `latest` or `cutoff`. H02 returns the actual `ExecutionReadEnvelope` directly, not an invented `{kind:snapshot}` wrapper. Read H09 frozen `inputs`, exact-R/T `observations`, and full fixed-interval `history` pages. Preserve first F and exact identity/R/T across pages, all original cursors and original record order; do not sort or reconstruct missing history. Missing observed geometry, position or work fraction stays unknown. The execution projection is read-only; Agent does not own clocks, holders, queues, inventory or physical interpolation.
5. An explicit user run/pause/resume/stop/reconciliation or device acceptance action uses H03 with the original displayed `expected_execution_revision`. Only latest actual Host-origin, current-owner access and the corresponding actual `allowed_session_controls` / device ID enable it. A cloud/history snapshot cannot authorize control. On RevisionConflict, refresh for user review without retrying the action. Do not automatically stop/restart production, release unsettled work, or claim a met target is settled terminal completion.
6. For data, preserve the exact original filters, UTC microsecond strings, dataset/aggregation/page size. Select exact execution R before query. The first telemetry page fixes selected F/devices; subsequent original cursors must keep it. A page budget ending early is partial. H11 exports **all rows matching that fixed query**, not just visible pages, using canonical first-page `{limit:200,cursor:null}` plus the actual selected F/devices or execution identity/R. Retain quality issues, original failed/waiting records and non-counted records.
7. H10 exports the selected original read origin/identity/R, optionally linked to a real frozen prediction Run input; use only PDF/HTML/CSV/JSON. H10 and H11 return `exporting` Tasks with distinct original operation, request and result kinds `execution_report` / `cloud_data_export`. Do not confuse admission with files being written. A destination must come from the actual current Native Agent selector: H10 purpose `export_execution_report`, H11 purpose `export_cloud_data`. Never invent a SelectedFileRef, accept arbitrary paths or reuse the other purpose. If the actual selector/Host export is not wired, preserve the unavailable result rather than report successful files.
8. Before leaving observation, read the actual latest lifecycle and unsettled commands, pending outputs and reservations. Report the real lifecycle/coverage/frontier and unresolved items. Exiting the observer sends neither stop nor cancel. Goal satisfied and fully settled terminal are separate facts. Do not imply observed freshness merely from nominal durations or a UI animation.

## Executable consumer

`integrations/agent/workflow.py::ExecutionWorkflow` runs these steps over an already authorized synchronous `send(full_request)`. The adapter calls the real `superfactory_<operation>` with that complete request and returns the real tool result; managed responses require the embedded original Response text. Pass the actual latest `Response.context` and authorized catalog, never a fabricated caller grant.

```python
flow = ExecutionWorkflow(send, actual_context, actual_catalog, actual_native_directory_selector)
configuration = flow.cloud({"kind": "configuration", "base_revision": actual_project_revision,
    "scenario_id": actual_scenario_id, "scenario_revision": actual_scenario_revision})
# If pending, call advance() at the next observation opportunity; it reads once.
# Only after user explicitly authorizes this actual policy:
prepared = flow.prepare(actual_confirmed_policy, confirmed=True)
# prepared["data"]["identity"] is usable only after status == completed.
view = flow.snapshot(actual_execution_identity, {"kind": "latest"})
# Only after the separate explicit run decision and actual access permit it:
ack = flow.control({"kind": "run"}, confirmed=True)
```

`cloud` also accepts the actual dataset/catalog/command/receipt selections. `view` and `view_pages` cover frozen inputs, observations and history. `query_first_page` / `query_next_page` preserve one fixed query; `export_data(confirmed=True)` requests its full export. `report(confirmed=True)` fixes the last actually read snapshot, while `exit_status(identity)` reads obligations without control. No method starts another worker or synthetic simulation. Keep `pending` through failures and use `recover()` after actual reauthorization. A finite method returning pending/partial requires observation later, not repeated production requests.

The existing Codex stdio launcher includes this product skill in its prompt and uses the actual bridge. Fixture/Host checks are component evidence; Native directory selection, real HTTPS execution and report/file acceptance require their own actual integration evidence.
