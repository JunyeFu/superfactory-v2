## Confirmed first-release choices

Read the [selected decisions](../../../../docs/00_项目基线/全量设计编码确认选择.json) and the applicable requirements in the canonical selected task JSON. Codex is the first actual client validation target; support for other clients requires real validation. Ask for critical missing inputs together and label editable example assumptions. Edit only the authorized draft and fields through shared Commands. Default repair variables are scheduling, selected template layout and explicitly allowed device instance count; phase durations, BOM, quality, extra personnel and cost changes require explicit authorization.

If the initial run meets the goal, deliver it immediately. Otherwise allow at most three feedback repair rounds, excluding the initial run. Each round checks the changed draft and performs a real run when runnable; retain actual changes/results. Stop on meeting the target, critical missing inputs or no effective supported change. Preserve partial drafts and explain missing capabilities. Draft undo/redo creates a new revision and never reverses production, human acceptance or file exports. Packaging’s 30-second experience trial target does not establish a hard solver timeout. Deliver Chinese engineering reports from the same actual result in four formats and a separate editable package.

# Super Factory workflows

For v2 production execution, use the [execution workflow](references/execution.md). H08 configuration → explicit H01 preparation → original Task/H09 recovery → explicit H03 run from latest Host-owner access → exact H02/H09 reads → explicit H10/H11 export. This is separate from the v1 prediction/repair workflow below. Never substitute `run_scenario` for unavailable execution. Prepared does not authorize run, and stopping observation never authorizes stopping production.

The [first-release scope baseline](../../../../docs/00_项目基线/首版交付基线.md) defines required and deferred work; the selected task JSON defines the current release projection. The platform MCP bridge is required, while external CAD/control connectors and other professional kernels are deferred. Scope design does not make a connected capability available.

Repository workflow package; it is not installed into global Codex configuration. The native bridge now connects through an OS-authenticated Windows pipe to the desktop managed Host. Desktop authorization and actual providers determine available tools. Discover the connected catalog before acting; absent providers remain missing and cannot be replaced with invented execution.

Read the [API and ownership contract](../../../../docs/03_架构与契约/首版类型格式与操作契约.md) for data meaning and the [integration workflows](../../../../docs/03_架构与契约/通用Agent接入与专业软件连接器.md) for the relevant task. These files define intended operations; the connected tool catalog defines actual availability.

For module authoring, inspect the [nine category contracts](../../../../docs/03_架构与契约/九类模块清单与消费者.md). Items, devices, resources, tasks, operations, transport, halls/compositions, professional providers, and media have different payloads and sample checks. Edit definitions through shared commands, then explicitly adopt the requested versions into the project. A hall/composition uses the existing templates category; do not create a tenth category or treat every payload as a device. A saved provider definition is not an implemented solver.

For new equipment batches, use `simulation-efficient-v1` in the canonical quality specification and [equipment modeling guide](references/equipment-modeling.md): show coarse motion and the finished workpiece first, reuse mechanisms/business rules by family, simplify noncritical details and accept one frozen batch. Thin stock may use decals/state meshes; simple rigid motion needs only its meaningful poses. Old micro-tolerances and capture counts are not new requirements; business/persistence correctness remains exact.

For device work, inspect supported geometry, behavior, ports and labels; edit the same draft the human can edit. Obtain a real render before judging appearance, and run a supported isolated cycle separately before judging production behavior. Save or adopt only the requested draft/instances.

For creating, replacing or reviewing a detailed equipment model, read [equipment modeling and external tools](references/equipment-modeling.md) before generating geometry. Tell the user which external modeling support is needed and what is actually available. Blender or a reproducible geometry program may produce the editable source and GLB; the platform's basic primitives are not a quality ceiling. Do not silently substitute boxes or simplified LOD for a requested detailed model. Follow the shared quality specification, register every model in the quality ledger, and review each exact exported model against the supervised reference. Import, animation or test success alone never establishes visual acceptance. The repository quality check is a delivery check, not a restriction on users importing private drafts.

For factory work, inspect product/BOM, existing objects and scope; construct a draft through shared commands, bind material/resource roles explicitly, and run the selected scenario. Explain waiting with actual object IDs, intervals and required conditions. Propose a changed scenario when requested; do not call a visually smooth flow an optimal or calibrated factory.

For a one-sentence production goal, read the [goal-driven factory workflow](../../../../docs/03_架构与契约/目标驱动厂房生成.md). Use query_module_library to select an actual native/imported community industry/product template compatible with the site's length, width and height. Resolve the production-day calendar, product specification, cycle/quantity, resource, supply and dimensional inputs from the user or clearly labeled template/module assumptions. Instantiate and fill the nine-category roles through shared commands; never bind the requested daily quantity to an output result.

Check material/port/resource references and declared footprint, height and space allowances with check_factory_draft; request a render of that revision, then run the actual scenario. Read accepted output at the stated time/window and destination in the chosen accepted unit. If the initial draft has sufficient inputs, passes checks and actually meets the modeled goal, save and export it directly: no change, revised RunId or comparison is required. Only for a shortfall or failed check, repair a supported and authorized condition and compare a new run, or explain why inputs, space or capabilities prevent a repair. Verify repair capability with a separate shortfall case rather than forcing it into every successful task. Stop on meeting the modeled goal, missing evidence/needed human decisions, unsupported scope or the task's finite execution budget; preserve the editable draft either way. This is template-driven generation with feedback, not an unbounded global optimizer.

For carton manufacturing, confirm the product family and required route. The initial sample uses purchased board for die-cut/fold-glued cartons with supported optional printing, inspection and bundling. Packing another product into an existing carton is a different factory. Count accepted cartons, not bundles; forming/manufacturing artifacts do not supply guessed production cycle times.

Scheduling edits change the authorized release/due dates, priorities, arrivals and calendar fields. Phase durations, BOM, quality, additional personnel and costs require explicit authorization for those fields. Actual start/completion follows dependencies and resources; moving a planned bar does not manufacture a result. Track a purchased or machined part through assembly and packaging using actual item/container relationships, not only the current camera view.

For packaging work, obtain product revision, material/connection and use conditions. Call actual packaging computation, preserve Pass/Fail/Undetermined and its supported scope, and return editable geometry/manufacturing outputs. Human acceptance and factory binding remain distinct; a rendered box or guessed cycle time is not a professional result.

For evaluation delivery, read the [report contract](../../../../docs/03_架构与契约/评估报告与数据导出.md) and discover whether export_evaluation is actually available. Select the requested scenarios/runs, metric scope, formats, and destination. PDF, offline HTML, CSV tables, and JSON must use the same result and unit/acceptance definitions. Without an actual run, export only a clearly marked design description. An evaluation report, editable project package, and community module package serve different purposes; prepare contribution files without publishing them automatically.

Keep edits on the project revision read from the host. On RevisionConflict, read the current context and reconcile the requested change; do not overwrite the user's edits. Running inventory, view playback and draft versions are separate. Report missing inputs or capabilities explicitly.

Use the user's existing authorization and selected project/file scope. This workflow does not authorize installing providers, configuring global clients, publishing, submitting entries, or sending files to other services. A private asset's availability does not grant redistribution rights.

## Concrete call and task discipline

Use the canonical [public API](../../../../docs/03_架构与契约/公开操作与宿主调用契约.json), the [DRF04 definition](../../../../docs/04_开发与验收/特征细化/DRF04_完整定义.json), and the [template adoption contract](../../../../modules/templates/instantiation.design.json). Names in prose are operations; actual tools are `superfactory_<operation>` only when tools/list exposes their implemented schemas. Do not register device editing capability IDs as extra tools.

Read the current Host, Project/DefinitionDraft scope and revision. An incomplete user utterance stays in a local form draft until required FactoryGenerationGoal fields are resolved. Quantity is `{value, unit}`; accepted_unit is a display concept mapped to Quantity.unit and AcceptanceScope.unit, not a new public field. Use the selected product revision, destination and acceptance stage. Template bindings select explicit ModuleRef id/version; saving a definition does not adopt it.

For an actual Project draft read, `get_object.params` is exactly `{"object_id":{"kind":"project","id":"<actual project id from get_context>"},"source":{"kind":"draft"},"node_index":null}`. The required names are `object_id` and `source`; `object_ref` is not an alias. Keep the canonical request envelope and actual scope/project identity. A rejected malformed read is not a read result; correct its shape before continuing, without changing authority or guessing data.

For multiple explicitly chosen acceptance points, keep the primary `acceptance_scope` and add only the chosen exact Product@revision/unit/location/stage tuples in optional `additional_acceptance_scopes`. Omit an empty list; do not send null. All scopes use the primary unit. Do not infer other sinks, count the same accepted quantity twice, or create artificial OrderLines to supply a missing goal. Existing order-mode rules remain in force; a manual Scenario acceptance goal cannot coexist with orders. Source goals must agree rather than overriding one another. A named `factory_check.aggregate_throughput_unverified` means static inspection has not computed a combined throughput; retain that result, distinguish it from missing geometry/material inputs, and use a separately admitted real Run to obtain actual acceptance when its inputs are valid. Do not turn that static row into Pass or invent per-scope quotas/completion times.

Preview fresh object IDs and rewritten internal references. Reuse an existing resource only through an explicit role-to-ID binding; do not duplicate the person, capacity, calendar or inventory. InstantiateTemplate.explicit_new_scenario_seed is null until supply and order choices are separately confirmed. Old Run items, claims, approvals and TaskIds never become a seed. Apply one atomic batch with the current base_revision and inspect changed_objects. Whole-object writes must respect the same authorized field scope as parameter writes; stop on PermissionDenied rather than switching tools.

render_view, run_scenario, compute_packaging, import_package, save_project, export_package and export_evaluation return TaskHandle, not their final artifacts. Read get_task for the returned task ID and originating operation; only its real completed TaskOutput supplies the render, run summary or files. A real run summary leads to get_run for frozen input, events, objects and full results. API Ok at admission is not target attainment. Keep explicit operation/project/revision identity on returned data.

Cancel an admitted task with cancel_task using action=`cancel`, then read its actual terminal state. If completion won, retain Completed and its result. CancelRequested is pending. Protocol notifications/cancelled cancel an outstanding MCP request, not a previously admitted Host task; this workflow uses ordinary business tools and does not presume the optional MCP Tasks extension. After disconnect, accepted work remains Host-owned; do not automatically resubmit an ambiguous edit or run.

For feedback, the initial run is round 0 and repairs are rounds 1..3, so there are at most four comparable capacity runs. Compute a proposal from actual waiting/shortfall, intersect it with available capabilities and the granted fields, and compare its typed before/after values. If there is no effective change, stop before apply/run. Every committed repair consumes one round, gets a fresh check and a real run when runnable, and retains the earlier Run unchanged. Do not rerun an identical proposal to consume the budget. Missing conditions -> missing_conditions; supported changes exhausted -> unrepairable_shortfall; three committed repairs exhausted -> finite_budget_exhausted. A cancelled task keeps its actual Task status and does not masquerade as one of these goal conclusions.

For timeline feedback, use the [shared axis definition](../../../../docs/02_交互设计/时间轴主轴与子轴完整定义.json): one Run/input/time, get_run Summary then Events pages, FullResult and matching ObjectsAt within computed_until_ms. Describe actual Job/phase/resource/wait IDs and intervals. TC01/TC02 and computed_until_ms are merged canonical carriers. Read JobState.execution_ref, WaitInterval.execution_ref/phase_ref and RunResult.phase_work_intervals. Missing actual history still displays unknown; do not reconstruct it from nominal durations or final inventory. Events include end-point point events; duration bands remain half-open. Input drag edits use the same ScenarioInput PutObject batch; actual bars remain read-only. The lower tools, default 160px timeline dock and separate description dock are controlled by the Window menu.

Save/export through actual Host-issued SelectedFileRef with matching purpose. Four formats read one frozen EvaluationReport; a single initial successful Run may have empty revised_run_ids and no comparison. Partial, cancelled or missing-input results keep their known scope and missing_conditions; they never become a whole-goal pass. Rights, human acknowledgment and permitted output fields use the same Commands policy as the UI. A design description without a Run uses design_description; it does not contain invented production metrics.

The current Host private edit grant records are merged and natively compiled; they are not Request/Schema/TS fields. All fifteen command branches normalize and authorize their full candidate effects under the current grant, including cumulative distinct create IDs and exact resource reuse. Do not send or claim a grant in JSON. The [connector definition](../../stdio-connector.design.json) defines the actual shared Host pipe and managed-response consumer, while keeping fixture, native process, Codex client and full product acceptance distinct. Render attachments require an actual render provider and are unavailable until that producer is connected. Keep a confirmed committed-repair counter in this generation session; do not derive it from the number of revised Runs. Stop after ambiguous connection loss, retaining the last confirmed count and proposal without an automatic resubmission.

Large results use the shared [managed response contract](../../../../docs/03_架构与契约/大结果传输设计.md). When structuredContent has outcome.status=`managed`, consume the complete original Response from the accompanying application/json EmbeddedResource; a bare result URI is not usable evidence. The bridge verifies the expected original schema, request/context and Run identity before emitting it. Branch on that recovered response: an embedded PermissionDenied or other error remains an error even though the outer envelope is `managed`. Never invent a resources/read tool, infer target attainment from the wrapper, or start another run to recover a transfer failure. Transport cancellation releases the owned read lease; it does not itself establish a business Task's Cancelled state. Canonical render-image attachments are validated separately after the typed task result is recovered.

For reconnect, retain the last confirmed TaskId, proposal and committed repair count; never replay an ambiguous edit or run. Native EOF revokes the old Host session. A fresh connection has no previous file tokens or task authority. Resume a known original Task only after the actual desktop main window explicitly grants that TaskId to the new session. Read-only access cannot cancel; control access still obeys current operations, project/definition scope and allowed_controls. These are native UI administration entries, not extra MCP tools or JSON grants. Authority changes never change the original Task/Run/input or reset the finite repair count.

## Executable finite workflow

`integrations/agent/workflow.py` consumes an already connected canonical MCP caller and Host-approved directory selections. `instantiate` obtains the current Host preview; `adopt_template` is a separate explicit commit. `run_factory` reads the actual Scenario goal, checks the current revision, consumes real Task states and Runs, and requests a typed proposal only after an actual shortfall or failed check. The proposal contains editable objects; the Host still authorizes their changed leaves.

Call `template_for_goal` before autonomous template selection. An exact ID match alone is insufficient when the actual library says `applicable=false`; retain its missing conditions and preserve the draft. A separately and explicitly selected private example may be exercised as a labeled model, while its measured industrial applicability remains unaccepted. Do not turn a successful example Run into library applicability evidence.

Catalog applicability evaluates the exact profile's declared industry/product and concrete site conditions. A private model may match its explicitly declared example site while retaining all Unknown/unmeasured source records; that match is not industrial measurement, geometry or capacity acceptance. Different declared site dimensions are outside that profile's concrete scope; changed regions or absent conditions stay unresolved. Run the actual same-revision factory checks and simulation after explicit adoption.

The initial successful Run uses zero repairs and no comparison. Identical proposals stop before submission; only confirmed edit commits count toward the three-round limit. Rejections preserve the candidate and are never retried. Prior Runs are read back unchanged before export. `status` describes the modeled goal; `delivery_complete` separately requires completed real save/export tasks. Render evidence requires a selected actual product view and an exposed renderer; absent render feedback remains explicitly unexecuted. The controlled CLI consumer fixtures are examples, not measured factory data or human/visual acceptance.

When an actual draft capture is selected, each confirmed revision refreshes both the request revision and its draft view's project revision, keeping the selected camera/LOD. An existing Run is a different explicit source: do not relabel its view as the current draft. Read it separately with `complete`/`wait_task` and retain its original input revision, RunId and time. The repair proposal receives the actual completed `render` task and its scene/limitations; its MCP image is delivered by that task's `get_task`, not by a fabricated URI or a redraw.

An explicitly requested capture must complete before proceeding to production. Missing registration, Unsupported, rejected admission, failed/cancelled capture stop and save the editable draft with the actual reason. A concurrent edit after the frame can still reject Run admission: preserve that new draft and the original frame, do not retry with a guessed revision. `render_complete`, modeled goal status and artifact `delivery_complete` are distinct. A rendered limitation or missing detailed Presentation does not become detailed-model or human acceptance.
